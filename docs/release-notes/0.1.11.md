# Aptly 0.1.11

0.1.10 이후 문서 탐색, 전송 범위 확인과 관리형 Codex 계정의 정책 참조를 개선합니다.

## 변경 사항과 관련 이슈

| 이슈 | 변경 | PR |
|---|---|---|
| [#127](https://github.com/abruption/aptly/issues/127) | 4개 언어 가이드를 짧은 목차와 9개 주제 문서로 분리하고 기존 앵커·링크 유지 | [#128](https://github.com/abruption/aptly/pull/128) |
| [#126](https://github.com/abruption/aptly/issues/126) | 신규·업데이트 사용자의 첫 대화형 설정에서 전송 범위 확인 | [#129](https://github.com/abruption/aptly/pull/129) |
| [#130](https://github.com/abruption/aptly/issues/130) | 관리형 계정 동기화에 대응하는 명시적 Codex 정책 홈 선택 | [#132](https://github.com/abruption/aptly/pull/132) |

첫 대화형 `aptly setup` 또는 `aptly set default`에서 아직 검토하지 않은 클라이언트별 전송 범위를 확인합니다. 선택지는 Aptly 개발자에게 보내는 정보가 아닌 OpenAI Decisions API에 전달할 작업 정보입니다. excerpt를 권장하지만 Enter는 기존 설정을 유지하고 미선택 상태는 none으로 설정합니다. `aptly set transmission --review`로 다시 확인할 수 있습니다. CI·비대화형·자동 설치는 선택하지 않으며 기존 동의를 조용히 넓히지 않습니다.

관리 도구가 기본 홈의 MCP 등록을 계정 홈에 동기화하면, 계정에만 수정한 절대 정책 경로가 다시 덮어써질 수 있습니다. 신규 `aptly setup --client codex --policy-source codex-home [--dry-run]`은 정상 소유권의 기존 표준 등록을 명시적으로 전환합니다. 서버는 전달된 절대 `CODEX_HOME`을 한 번 해석해 정책·재시도·맥락·통계가 같은 정책을 참조하도록 합니다. 변수가 누락되거나 유효하지 않으면 다른 홈으로 추정하지 않고 중단합니다.

모든 등록된 서버를 먼저 갱신하고, 기본/정본과 각 대상 계정에서 전환을 검토하십시오. 기본 홈도 `CODEX_HOME="$HOME/.codex"`를 명시해야 합니다. 고정·공유 참조는 전환하지 않으면 유지되며 기존 정책 내용·전송 선택·원장 경로·통계 이력·Hook 신뢰는 이동하거나 초기화하지 않습니다. 사용자 정의 실행기나 무관한 설정 차이는 자동 복구하지 않습니다. 구체적인 절차는 [문제 해결](../guide/ko/troubleshooting.md#guide-account-home-recovery)을 따르십시오.

## 설치와 검증 범위

`npm install -g aptly@latest --allow-scripts=aptly`로 설치할 수 있습니다. 이번 게시 검증 시점의 npm `latest`는 0.1.11입니다. 관련 호스트와 MCP를 중지한 뒤 갱신하고 설정을 확인한 다음 재시작하십시오. 새 Hook의 Codex 신뢰 승인은 사용자 검토가 필요합니다.

합성 회귀·격리 설치·격리 계정 동기화 시험과 아래의 실제 호스트 전환 확인은 구분합니다. 이 결과는 native 모델·effort 관측의 증거가 아닙니다. 정책 소스 선택은 호스트 전체 설정의 출처 인증이 아닙니다. 통계의 기본 비활성·POSIX 범위·별도 native 메타데이터 동의와 실제 effort 미관측 한계는 유지합니다. 상세 검증·게시 경계는 [실제 게시 기록](../releases/0.1.11.md)을 참고하십시오.

## 알려진 문제와 임시 실행 방법

0.1.11에서 `codex-home` 정책 참조를 선택한 뒤 `CODEX_HOME`이 없는 일반 터미널에서 CLI 설정 명령이 실패하는 문제를 [#135](https://github.com/abruption/aptly/issues/135)로 추적합니다. 읽기 전용 점검으로 재현했으며 이 릴리스에 수정이 포함됐다고 주장하지 않습니다. 기본 홈을 대상으로 실행할 때는 다음처럼 환경을 명시하십시오. 관리형 계정에서는 해당 계정의 의도한 절대 홈 경로를 사용하십시오.

```sh
CODEX_HOME="$HOME/.codex" aptly setup --check --client codex
```

일반 CLI의 홈 선택 문제와 실행 중 MCP 서버의 엄격한 `CODEX_HOME` 검사는 구분합니다. MCP의 누락·잘못된 홈 거부를 우회하거나 다른 계정 홈으로 대체하지 마십시오.
