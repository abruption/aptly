# Aptly 0.1.7

릴리즈 준비 중입니다. 아직 `v0.1.7` 태그·npm 게시·GitHub Release를 생성하지 않았습니다. 준비와 실제 게시 파일·서명·provenance 검증을 구분합니다.

## 주요 변경

Aptly 0.1.7은 **OpenAI Decisions API에 전송할 작업 정보의 범위**를 운영자가 선택하도록 합니다. Aptly 개발자에게 작업을 전송하는 기능을 뜻하지 않습니다. confidence 기본 동작은 유지하며 별도 분류 파일럿과 회귀 검증을 기록합니다.

- **신규 등록의 첫 선택:** v2 `unselected` 상태는 자동 분류 요청·호출 결합·복구 참조를 만들지 않고 원래 호출을 보존합니다. 대화형 `aptly set default`는 미선택 호스트에만 묻고 Enter는 `none`입니다. 명시적 `--transmission`이 없는 비대화형 setup·postinstall은 전송 범위를 자동 선택하지 않습니다.
- **전송 범위:** `none`은 자동 전송을 끄고 원래 호출을 보존합니다. `description`은 부모가 제공한 설명만 허용하며 없으면 유료 요청 전에 보충을 요청합니다. native 본문·라벨로 자동 대체하지 않습니다. 보충 전 `defaults`는 스폰을 차단하고 `advisory`는 안내만 반환합니다. `excerpt`는 기존 발췌와 명시 설명을 허용합니다. 적용 모드와 전송 범위는 별개이며 명시적 직접 추천 요청은 이 자동 전송 설정으로 금지하지 않습니다.
- **명시적 설정과 기존 사용자:** `aptly set transmission none|description|excerpt`, `--show`, `setup --transmission`을 제공합니다. 기존 v1은 바이트를 유지하고 legacy excerpt로 표시합니다. 명시 변경만 v2와 소유권 기록을 함께 갱신합니다. 수정된 정책을 자동 인수하지 않으며 키·원장·불명 요청을 삭제하지 않습니다. 호스트별 복구와 선택 중 동시 변경 보호를 유지하고 scope만 바꿀 때 기존 advisory 모드를 보존합니다.
- **정책 변경 경계:** 진행 중 결과·retry·fresh는 현재 정책을 다시 확인하고 변경되면 적용하지 않습니다. 이미 시작한 전송을 회수하는 기능은 아닙니다. 이전 native 호출 결합·불명 유료 결과를 새 ID로 우회하지 않습니다. 명시 모델·effort·역할·필수 이력·권한과 기존 차단을 보존합니다.
- **confidence 평가:** 8개 합성 작업을 두 번씩 실제 MCP→Decisions로 분류했습니다. 작성자가 사전에 정한 기대 분류와 14/16회 일치했으며 번역 검토 2회는 routine 기대와 달리 simple을 추천했습니다. confidence 0.43의 이 불일치는 실제 자식 품질 저하나 숫자 cutoff의 타당성을 입증하지 않습니다. 0·낮은 값의 기존 허용, 실제 provider의 누락 거절, 일반 Router·저장 결과의 선택 메타데이터를 무료 회귀로 구분합니다.
- **문서 현행화:** 사전 설명 등록·새 설명으로 한 번 재추천하는 문맥 보충·완료 추천을 재사용해 추가 분류하지 않는 fresh 준비를 구분하고 4개 언어에 동기화합니다. 설명 작성과 민감 패턴 검사는 비민감성·익명화·사용자 동의를 인증하지 않습니다.

## 설치와 업데이트

다음 명령은 **0.1.7 게시 후** 최신 안정 버전을 설치합니다. 게시 전 `latest`는 여전히 0.1.6일 수 있습니다. Node.js 24 이상이 필요합니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly set default
aptly set env OPENAI_API_KEY
aptly --version
```

첫 설정에서 운영자가 전송 범위를 선택합니다. 기존 키를 설정한 업그레이드에서는 키를 다시 입력할 필요가 없습니다. 옵션 미지원 npm은 [설치 안내](../guide/ko.md#설치)의 `--ignore-scripts`와 명시적 설정 절차를 사용하십시오.

업데이트 전 관련 호스트·MCP·CLI writer를 중지하고 JSON 원장·완료 캐시·`unknown`·비용 기록과 유효한 SQLite gate·journal을 보존하십시오. 0.1.2 이전의 원장 전환은 설치 안내의 오프라인 절차를 따르십시오.

```sh
aptly update
aptly setup --client all
aptly set transmission --show
aptly --version
```

현재 적용 모드를 보존하려면 `--mode`를 생략하십시오. 기존 v1은 자동으로 더 좁거나 넓은 범위로 바뀌지 않습니다. 운영자가 원하는 경우 아래 대안 중 하나로 명시 전환하십시오.

```sh
aptly set transmission description --client all
```

이는 호출자 설명만 허용하는 예이며 `none` 또는 `excerpt`도 선택할 수 있습니다. 설정 변경 후 호스트·MCP를 재시작하십시오. 실행 경로·사용자 래퍼와 키는 자동 이전하지 않습니다. Codex에서 새 Hook 검토·신뢰 승인이 필요하면 `/hooks`에서 진행하십시오. 재시작하면 기존 프로세스의 복구·준비 참조는 유지되지 않습니다.

## 검증과 남은 한계

이번 준비 후보에서 통합 테스트 508개·타입/빌드·fixture PoC·설치된 tarball의 compiled CLI/exports/MCP/cache·다국어 문서·릴리스 검사(소스 248개·패키지 80개)를 통과했습니다. compiled CLI는 0.1.7을 출력합니다. mock wire·무전송·취소/만료·정책 변경·소유권 복구는 합성 시험이며 실제 API/native 실행으로 표현하지 않습니다. 별도 서브에이전트가 릴리스 범위와 문구를 읽기 전용으로 검토했습니다. 준비 PR의 원격 CI와 실제 게시 후 registry 검증은 별도로 확인합니다.

[confidence 파일럿](../CONFIDENCE_EVALUATION.md)은 분류 기준 일치·토큰·분류 지연을 기록한 소규모 시험입니다. 16개의 독립 업무나 confidence 보정, 실제 자식의 산출물 품질·총비용 평가가 아닙니다. 사후 임계값 집계로 기본 cutoff를 정하지 않았습니다. 알려진 비밀 패턴 검사는 완전한 탐지가 아니며, 에이전트의 설명 생성·후속 실행과 호스트 권한을 Aptly가 소유하지 않습니다. 전송 범위가 좁아져도 추천 품질이 같다는 주장은 하지 않습니다.

이번 준비는 confidence 평가용 추가 분류·native 자식 시험·전역 재설치·운영 설정 변경을 포함하지 않습니다. 검수용 서브에이전트 선택에는 Aptly 추천 1회를 사용했으며, 이 오케스트레이션과 검수 에이전트의 비용은 기존 파일럿 16회·비용에 포함하지 않습니다. 준비 PR 병합 뒤 정확한 main CI 성공과 별도 게시 지시를 확인한 후 [Actions OIDC 배포 절차](../RELEASING.md)를 따릅니다. 새 태그·npm 파일·서명·provenance가 확인되기 전에는 게시 완료라고 표현하지 않습니다.
