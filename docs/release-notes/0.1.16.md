# Aptly 0.1.16

독립 위임의 프로필 전달 안내와 패키지 시험 진단을 보완하고 문서를 간소화합니다.

## 변경 사항

- **독립 위임 안내:** `prepare_fresh_delegation`이 모델·effort를 필수 인자로 표시합니다. 전체 `next_call.arguments` 전달을 안내하고 사용자·호스트 제약이 금지하거나 불명확하면 중단하도록 명시합니다. 새 `spawn_application` 객체는 호출자 안내이며 실행·권한·준비 결과와의 일치를 보증하지 않습니다. 엄격한 응답 소비자는 추가 객체를 허용해야 합니다. ([#170](https://github.com/abruption/aptly/issues/170), [PR #171](https://github.com/abruption/aptly/pull/171))
- **문서 간소화:** 네 언어 README·설정·설치·전송 안내의 중복을 줄이고 이전 링크를 보존했습니다. ([#166](https://github.com/abruption/aptly/issues/166), [PR #167](https://github.com/abruption/aptly/pull/167))
- **개발용 시험:** stable 패키지 스모크에 실패 단계·허용된 stderr 분류·자식 종료 정보를 추가했습니다. 래퍼의 신호 처리기를 자식 생성 전에 등록하고 테스트 정리를 보강했습니다. 기존 간헐 MCP 연결 종료의 원인이 해결됐다는 의미는 아닙니다. 제품 실행기의 시간 제한·검증은 유지합니다. ([#168](https://github.com/abruption/aptly/issues/168), [PR #169](https://github.com/abruption/aptly/pull/169), [#172](https://github.com/abruption/aptly/issues/172), [PR #173](https://github.com/abruption/aptly/pull/173))

## 업데이트

관련 호스트·MCP·CLI 프로세스를 중지한 뒤 전역 설치에서 실행하십시오.

```sh
aptly update
aptly setup --client all
```

MCP·호스트를 재시작하십시오. 키·전송 선택·원장·통계를 초기화할 필요가 없습니다. stable 실행기를 쓰는 경우 보존된 사본도 [명시적으로 갱신](../guide/ko/configuration.md#guide-stable-launcher)하고 변경된 Codex Hook은 `/hooks`에서 승인하십시오. [설치·업데이트 안내](../guide/ko/installation.md#guide-package-updates)를 참고하십시오.

## 검증과 게시 상태

로컬 테스트 856개 중 840개 통과·실패 0개·임시 볼륨 권한 조건으로 16개 제외를 기록했습니다. 타입·문서·패키지·fixture MCP 검사가 통과했으며, 해당 볼륨의 stable 실행 단계는 신뢰 조건을 완화하지 않고 건너뛰었습니다. 원격 CI는 준비 HEAD와 병합 main을 구분해 확인합니다. 모의 시험에서는 실제 Decisions API 호출, 서브에이전트 실행, 호스트가 설정을 다시 읽는 과정을 확인하지 않았습니다. 정확한 main CI 7개와 [Actions OIDC 게시](https://github.com/abruption/aptly/actions/runs/43679018205/attempts/1) 3개 job이 성공했습니다. npm latest 0.1.16, artifact/registry 일치·서명·소스/태그/workflow/run provenance를 확인했습니다. [게시 기록](../releases/0.1.16.md)을 참고하십시오.
