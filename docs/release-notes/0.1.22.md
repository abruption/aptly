# Aptly 0.1.22

## 업데이트

macOS와 Linux에서 `aptly update`는 패키지를 갱신한 뒤 소유권 기록과 일치하는 Codex·Claude Code MCP 등록을 관리형 `npx`로 이전합니다. 기존 직접 실행과 `stable` 등록이 대상입니다. 결과는 호스트별로 표시하며 사용자 지정 등록은 보존합니다. Windows에서는 패키지만 갱신합니다. [이슈 #219](https://github.com/abruption/aptly/issues/219) · [PR #220](https://github.com/abruption/aptly/pull/220)

관련 호스트·MCP·CLI 프로세스를 중지한 뒤 `aptly update`를 실행하십시오. macOS·Linux에서 **0.1.21로부터 업데이트할 때는 같은 명령을 두 번 실행**하십시오. 첫 번째 실행에서 새 CLI를 설치하고, 두 번째 실행에서 기존 등록을 이전합니다. 호스트를 재시작한 뒤 Codex에서는 변경된 Hook을 `/hooks`에서 승인하십시오. [설치·업데이트 안내](../guide/ko/installation.md#guide-package-updates)

관리형 `npx`는 설치한 Aptly와 의존성의 고정 사본을 사용해 MCP를 오프라인으로 시작합니다. 기존 전역 Aptly 경로가 사라져도 이 사본을 쓸 수 있습니다. 신뢰할 수 있는 경로에 설치된 Node.js 24 이상과 함께 제공되는 npm이 필요합니다. [관리형 실행기 안내](../guide/ko/configuration.md#guide-stable-launcher)

## 분류 요청 취소와 응답 처리

- MCP 요청이 취소되면 분류 요청에도 신호를 전달하고 로컬 대기와 잠금을 정리합니다. 비용을 이미 예약했다면 결과 미확정 기록을 남겨 같은 ID의 중복 요청을 막습니다.
- Decisions 응답의 원시 바이트를 기준으로 65,536바이트 상한을 적용합니다. UTF-8 문자 중간에서 응답이 나뉘어도 같은 결과를 반환합니다.
- 4개 언어 설치 가이드에 등록 상태를 점검하는 방법을 추가했습니다. [이슈 #217](https://github.com/abruption/aptly/issues/217) · [PR #218](https://github.com/abruption/aptly/pull/218)

## 실기 검증

PR #218의 후보 패키지로 두 Mac, KR·US Linux, Windows에서 합성 작업을 사용해 Decisions API를 기기별로 한 번씩 호출했습니다. 같은 요청 ID를 다시 보내면 캐시가 사용됐습니다. PR #220의 후보 패키지로 맥미니와 KR·US Linux에서 Codex·Claude Code의 관리형 실행기를 시험했습니다. Windows에서는 고정 버전 `npx`로 Codex의 MCP 도구 응답과 Claude Code의 MCP 연결을 확인했습니다.

## 게시

GitHub Actions에서 OIDC로 게시했습니다. 게시 확인 시점의 npm `latest`는 0.1.22였으며, 배포 파일은 Actions에서 검증한 아카이브와 일치했습니다. 격리 설치, npm 서명, 출처 증명 검사도 통과했습니다. 자세한 내용은 [게시 기록](../releases/0.1.22.md)을 참고하십시오.
