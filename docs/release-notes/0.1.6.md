# Aptly 0.1.6

**게시 전 릴리즈 노트 초안입니다.** 준비 PR 병합·정확한 main CI 확인과 별도 게시 지시가 남아 있습니다. 0.1.6 태그·npm 게시·이번 버전의 서명 및 provenance 검증은 아직 수행하지 않았습니다.

## 주요 변경

Aptly 0.1.6은 상속 추천을 같은 독립 작업의 별도 호출로 준비하는 경로를 추가하고, 다국어 작업 설명 검사와 설정 변경 실패 복구를 보완합니다. Windows ACL 검사에는 안전한 실패 분류와 제한된 native 검증을 추가합니다.

- **별도 독립 위임 준비:** `prepare_fresh_delegation`은 완료된 추천을 재검증해 별도 Codex 호출 인자를 제공합니다. 호출자는 같은 독립 작업·완전한 독립 지시·불필요한 상속 이력과 호스트가 원래 호출을 차단했다는 결과를 선언해야 합니다. 추가 분류를 하지 않고 원래 `all` 호출도 재작성하지 않습니다. 필수/불명 이력, 실행됨/불명 원래 결과, 고정 역할·resume·검증하지 않은 실행 인자는 준비하지 않습니다.
- **지시와 관측 구분:** 원래 호출을 바꾸어 재제출하는 것과 조건을 충족한 별도 새 호출을 구분해 안내합니다. `fresh_delegation` 관측은 준비 결과와 최근 거절을 분리하며 실제 실행은 계속 `not_observed`입니다.
- **다국어 맥락 검사:** 공백 없는 상세 일본어·중국어와 영문 식별자가 섞인 설명을 세 입력 경로에서 공통으로 검사합니다. 고정 로케일 단어 분할과 문자 다양성·단순 패딩 검사를 사용하고, 기존 바이트·민감 문자열·요청 결합·모델 선택 보존 제약은 유지합니다. 짧거나 모호한 입력은 여전히 거절될 수 있습니다.
- **설정 변경 실패 복구:** POSIX 권한을 rename 전에 stage에 정확히 적용해, 교체 후 권한 오류가 복구 목록에서 빠지는 경로를 제거합니다. 새 파일·제한적 umask·다른 작성자 변경을 검증하고 동시 변경과 일반 복구 실패를 구분합니다. Windows DACL 보존과 호스트별 부분 성공은 유지합니다.
- **Windows ACL 진단:** 시간 초과·알려진 실행 시작 오류·정책 거부·스크립트/프로세스 오류·예상 밖 출력을 안전한 범주로 구분합니다. 운영 기본 제한은 10초로 유지하며 CI의 첫/후속 ACL probe만 최대 30초를 허용합니다. ACL 변경을 자동 재시도하지 않습니다.

## 설치와 업데이트

영속 원장에 접근하는 관련 호스트·MCP·CLI writer를 먼저 중지하십시오. JSON 원장·완료 캐시·`unknown`·비용 기록과 유효한 SQLite gate·journal은 보존하십시오. 0.1.2 이전 버전은 [설치·원장 전환 안내](../guide/ko.md#설치)의 오프라인 절차를 확인하십시오. 이번 업그레이드만을 이유로 원장이나 잠금 파일을 초기화하지 마십시오.

다음 명령은 **게시 후 최신 안정 버전**을 설치합니다. 검증 가능한 전역 npm 설치에서 Aptly 0.1.3 이상을 사용 중이면 다음 순서로 업데이트할 수 있습니다.

```sh
aptly update
aptly setup --client all --mode defaults
aptly --version
```

`update`는 설치 스크립트를 실행하지 않으므로 명시적 `setup`과 호스트·MCP 재시작이 필요합니다. 기존 실행 경로·사용자 래퍼를 자동 이전하거나 API 키를 다시 저장하지 않습니다. 현재 모드와 다른 설정을 적용하려면 설치 안내를 먼저 확인하십시오.

새 설치는 다음과 같습니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly setup --client all --mode defaults
aptly set env OPENAI_API_KEY
aptly --version
```

기존 키가 설정된 수동 업그레이드에서는 키를 다시 입력할 필요가 없습니다. 옵션 미지원 npm은 `--ignore-scripts` 설치 후 명시적 `setup`을 사용하십시오. 재시작 후 새 MCP 도구와 Hook 상태를 확인하고, 새 Hook 검토·신뢰 승인이 필요한 Codex에서는 `/hooks`에서 진행하십시오. 프로세스에 연결된 기존 복구·준비 참조는 재시작 후 복구되지 않으므로 진행 중 작업의 상태를 먼저 확인하십시오.

## 지원 및 검증 경계

새 준비 API는 **호스트가 원래 호출의 차단 결과를 보고한 뒤** 사용합니다. 준비와 추천은 권한 승인이나 사용자 의도 증명이 아닙니다. 작업 의미의 동일성·독립성은 호출자가 선언하며, 후속 native 실행과 권한은 호스트가 담당합니다. 반복 준비는 자식 실행 1회를 보장하지 않습니다.

같은 프로세스·원래 5분 수명·128개 참조 한도와 정책/후보/등록 컨텍스트 검사를 유지합니다. 최종 검사에서 응답이 거절돼도 불변 준비 digest가 남을 수 있으며 다른 작업을 재시도하려고 이를 삭제하지 않습니다. 캡처한 이벤트 검사는 이후 호스트 설정·취소를 자동 관측하지 않습니다. [복구·준비 계약](../SPAWN_CONTEXT.md#intentional-fresh-delegation)을 참고하십시오.

기능 개발 단계에서는 네 수정의 통합 테스트 478개와 제한된 native 시험을 수행했습니다. 이는 새 릴리즈 후보의 준비 검증이나 실제 게시 파일 검증을 대신하지 않습니다.

- Codex CLI 0.167.0의 runtime 후보 `9bdf027`에서 세션 소유자가 독립 작업의 Aptly 기본값 선택을 허용한 조건으로, 원래 `all` 차단·분류 1회·호출자 준비·별도 `none`·실제 Luna/max 자식 결과를 확인했습니다. 명시적 상속 요구는 `all`과 차단 상태를 유지하고 자식을 생성하지 않았습니다. 중간 후보의 부모 후속 처리 실패도 보존했습니다.
- Windows native 검증은 정확한 후보 `21dbf39`의 [실행 42338319959](https://github.com/abruption/aptly/actions/runs/42338319959)에서 첫/후속 ACL 검사, 정책 거부·스크립트 오류 범주와 자격 생성·갱신·삭제·마이그레이션·정리를 확인했습니다. 이전 Windows CI 실패의 원인은 여전히 미확정입니다. 이 성공으로 운영 전반의 안정성이나 과거 실패 원인을 증명하지 않습니다.
- Claude Opus 5.5와 Gemini 4 Argon Medium의 자료 기반 독립 검수에서 제기된 수정 사항을 반영하고 별도 회귀로 확인했습니다. 검수 모델이 실제 Windows·Codex 시험을 직접 수행한 것은 아닙니다.

CJK 단문·ICU 분할 경계와 기존 파일시스템 check/rename 사이의 경쟁 한계가 있습니다. 모든 언어의 의미 충분성, 모든 부모 모델의 후속 호출, 전체 작업 비용 절감을 새로 입증한 릴리즈가 아닙니다. 낮은 confidence 정책 [#14](https://github.com/abruption/aptly/issues/14)와 더 넓은 공유 정책 [#15](https://github.com/abruption/aptly/issues/15)는 별도 범위로 유지합니다.

이번 준비는 새 유료/native 시험·전역 설치·운영 설정·키 이전을 수행하지 않습니다. 준비 PR 병합 후 정확한 main CI와 별도 게시 지시를 확인해야 합니다. 태그 push는 Actions OIDC 게시를 시작하므로, 실제 게시 뒤 source SHA·run·attempt·artifact/registry digest·서명·provenance를 각각 새로 검증해야 합니다. [배포 절차](../RELEASING.md)를 참고하십시오.
