# Aptly 0.1.21

## 변경 사항

- Codex가 `config.toml`을 다시 저장하면서 Aptly 설정의 끝을 표시하는 주석 앞에 다른 설정을 추가하면 API 키 등록이 `managed_mcp_changed`로 실패할 수 있었습니다. 이제 Aptly 설정값이 기존 등록 기록과 일치하면 키를 등록할 수 있습니다. 다른 Codex 설정과 Hook 신뢰 상태는 보존합니다. [이슈 #211](https://github.com/abruption/aptly/issues/211) · [PR #212](https://github.com/abruption/aptly/pull/212)
- Windows 검증 도구는 부모 ID를 대조해 연결된 서브에이전트 기록을 찾습니다. 기록 저장이 늦어지면 잠시 기다렸다가 다시 읽습니다. 이 과정에서 새 Decisions 요청이나 서브에이전트 호출은 발생하지 않습니다. [PR #212](https://github.com/abruption/aptly/pull/212)
- 한국어·영어·일본어·중국어 간체 설치 가이드에 [Windows PowerShell 설정 안내](../guide/ko/installation.md#guide-windows-powershell)를 추가했습니다. [이슈 #209](https://github.com/abruption/aptly/issues/209) · [PR #210](https://github.com/abruption/aptly/pull/210)

## 검증

수정한 도구로 Windows 10 x64에서 실행한 Aptly 0.1.20의 기록을 다시 읽었습니다. Codex 서브에이전트가 `gpt-6-luna / max`로 작업을 마치고 예상한 결과를 반환했음을 확인했습니다. 0.1.21을 준비하면서 Decisions API를 새로 호출하지 않았습니다.

## 업데이트

전역 설치를 업데이트하려면 관련 호스트·MCP 서버·CLI 프로세스를 중지하고 다음 명령을 실행하십시오.

```sh
aptly update
aptly setup --client all
```

설정 후 호스트를 재시작하십시오. stable 실행기를 사용한다면 [보존 사본](../guide/ko/configuration.md#guide-stable-launcher)도 갱신하십시오. 자세한 내용은 [설치·업데이트 안내](../guide/ko/installation.md#guide-package-updates)를 참고하십시오.

## 게시

GitHub Actions에서 OIDC로 게시했습니다. 게시 당시 npm `latest`는 0.1.21을 가리켰으며, 배포 파일은 Actions에서 검증한 아카이브와 일치했습니다. 격리 환경에서 CLI 설치를 확인했고, npm 서명과 출처 증명도 검증했습니다. 자세한 내용은 [게시 기록](../releases/0.1.21.md)을 참고하십시오.
