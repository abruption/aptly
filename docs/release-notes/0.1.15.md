# Aptly 0.1.15

Codex 기본 홈을 사용할 때 MCP 서버가 시작되지 않는 문제를 수정합니다.

## 변경 사항

- `@codex-home` 정책을 사용하는 MCP에서 `CODEX_HOME` 환경변수가 없으면 OS 사용자 홈의 `~/.codex`를 자동 선택합니다. 0.1.14에서 이 경우 `policy_source_home_invalid`로 초기화가 종료되던 문제를 해결합니다. ([#160](https://github.com/abruption/aptly/issues/160), [PR #161](https://github.com/abruption/aptly/pull/161))
- 명시한 절대 경로가 우선하며 빈 값·상대 경로·제어 문자가 포함된 값은 계속 거절합니다. 고정 정책 경로와 클라이언트 구분은 유지합니다.
- 기본 홈의 실제 stdio MCP 시작과 명시적 계정 홈의 우선순위를 회귀 테스트에 추가하고 네 언어 설정 안내·CLI 도움말을 갱신합니다.

## 업데이트와 호환성

```sh
npm install -g aptly@latest --allow-scripts=aptly
```

MCP·Codex를 재시작하십시오. 기본 홈을 사용하는 세션은 `CODEX_HOME`을 별도로 지정할 필요가 없습니다. 사용자 지정 계정 홈을 쓰는 관리자는 해당 `CODEX_HOME`을 계속 전달해야 합니다. 값이 없으면 기본 홈의 정책과 전송 범위가 적용되며 사용자 지정 계정을 자동 탐색하지 않습니다. 키·전송 선택·원장·통계 이력을 초기화할 필요가 없습니다.

기존 stable 실행기를 사용하는 경우 새 전역 패키지 설치만으로 보존된 런타임은 갱신되지 않습니다. 의도한 호스트 홈에서 dry run을 검토한 뒤 명시적으로 마이그레이션하십시오.

```sh
aptly setup --client codex --migrate-launcher --launcher stable --dry-run
aptly setup --client codex --migrate-launcher --launcher stable
```

변경된 Hook은 `/hooks`에서 검토·승인하십시오. 상세 내용은 [설정 가이드](../guide/ko/configuration.md)를 참고하십시오.

## 검증과 게시 상태

PR #161에서 독립 Claude Opus 5.5 검토 후 문서·회귀 테스트를 보완했습니다. Rebut Astra 응답은 `invalid_output`으로 유효 리뷰에서 제외했습니다. 새 기본 홈 stdio 테스트는 기존 0.1.14에서 실패하고 수정본에서 통과했습니다. 수정 후보의 로컬 회귀 843개 중 827개 통과·실패 0개·임시 볼륨 권한 조건으로 16개 제외와 타입·빌드·문서·패키지 검사를 기록했습니다. 실제 유료 Decisions 호출·native 자식 실행·기존 호스트 재로딩을 검증한 결과는 아닙니다. 버전 준비와 실제 게시 결과는 별도로 확인합니다.
