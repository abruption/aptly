# Aptly 0.1.10

2026-11-10에 실제 소스 `2acf74ca48c38d6541ba16f04f2e5054bd633ecb`의 annotated `v0.1.10` 태그로 [Actions OIDC 게시](https://github.com/abruption/aptly/actions/runs/42768525205/attempts/1)를 완료했습니다. npm `latest`는 0.1.10이며 archive 일치·npm 서명·인증서 기반 provenance를 검증했습니다. 준비 기반 main `7589cef9c1f5ed72725e6feeaff84487635914db`와 실제 태그 소스를 구분합니다. 준비는 [#122](https://github.com/abruption/aptly/issues/122)·[PR #123](https://github.com/abruption/aptly/pull/123), 게시 기록은 [#124](https://github.com/abruption/aptly/issues/124)와 [실제 게시 근거](../releases/0.1.10.md)에서 관리합니다.

## 주요 변경

### 선택형 로컬 실행 통계

`aptly stats`로 추천과 실행 관측의 관계를 확인합니다. 수집은 기본 비활성이며 기존 설치·postinstall에서 자동으로 켜지지 않습니다. 초기 수집 지원은 POSIX이며 Windows의 일반 Aptly 사용과 Node.js 24 이상 지원은 유지합니다.

0.1.10 이상으로 업데이트하고 기존 Aptly 설정이 있는 환경에서 다음 명령을 사용하십시오.

```sh
aptly stats
aptly stats enable --client codex
aptly stats --today --client codex
aptly stats disable --client codex
```

활성화 후 호스트와 MCP를 재시작하십시오. Codex에서는 `/hooks`에서 새 관찰자를 검토하고 신뢰를 승인해야 합니다. 신뢰를 자동 등록하거나 우회하지 않습니다. `--today`는 실행 완료일이 아닌 연결 기록 최초 생성일의 UTC 날짜를 사용합니다.

추천, 실제 도구 인자의 일치, 호스트가 보고한 모델 증거는 서로 구분합니다. `model_match`, `model_mismatch`, `model_changed`, `unknown`, `pending`, `expired_pending`, `application_unconfirmed`를 표시하고 advisory도 별도로 집계합니다. `blocked`, `explicit_preserved`, `unbound`는 모델 비교 분모에 포함하지 않습니다. 정확한 정식 모델명만 비교하며 Claude 별칭 `haiku`·`sonnet`·`opus`·`fable`은 정식 모델 증거로 해석하지 않습니다.

실제 effort는 미관측입니다. 모델 일치는 사용자 수용·작업 품질·비용 절감을 뜻하지 않습니다. 토큰·비용 합계나 계정 잔여 한도도 제공하지 않습니다. 누락·지연·용량 초과로 이력이 불완전할 수 있으며, 일치 표시는 보존된 증거에 한정됩니다. 위임과 자식 기록은 각각 10,000건으로 제한하고 자동으로 정리하지 않습니다.

### 비공개 저장과 추가 동의

통계는 예산 원장과 별개인 비공개 `stats.sqlite`, `stats-config.json`, HMAC 비밀키 `stats-key`를 사용합니다. 기록에 작업 원문·대화 기록·원시 ID·경로·오류·자격 증명을 저장하지 않습니다. 통계 조회는 API나 자격 저장소에 접근하지 않으며 업데이트 알림도 실행하지 않습니다.

Codex의 task-name 응답과 native 자식을 연결하려면 별도로 다음 옵션에 동의해야 합니다.

```sh
aptly stats enable --client codex --codex-native-metadata
```

정확한 자식 ID·부모·작업 경로를 확인하는 native SQLite 메타데이터만 읽으며 대화 기록 조회·복구·호스트 패치는 하지 않습니다. 읽기 과정에서 기존 SHM 읽기 표시가 갱신될 수 있습니다. 미지원·이전된 저장소나 모호한 연결은 미확인으로 남깁니다.

수집 해제·설정 제거 또는 옵션 없는 Codex 재활성화는 native 메타데이터 동의도 해제합니다. 해제 시 데이터와 키는 보존하고, 변경되지 않은 소유 관찰자만 제거합니다. 사용자 정의·수정·중복 관찰자는 보존하고 알려진 충돌을 보고합니다. 명시적 모델·effort·역할·이력·권한과 기존 키·예산·전송 범위는 바꾸지 않습니다.

### 의존성과 CI 유지보수

Actions checkout 7.0.1, setup-node 7.1.0, download-artifact 8.0.2, upload-artifact 7.0.2를 고정 SHA로 사용합니다. download-artifact는 기본적으로 산출물 digest 불일치를 오류로 처리하며 기존 archive SHA-256 재검증도 유지합니다. 개발용 `@types/node`는 26.6.6으로 갱신하고 Node 24·26의 빌드·테스트·설치 패키지 CI를 유지합니다. 타입 패키지 변경이 최소 실행 버전을 26으로 올리는 것은 아닙니다.

## 설치와 업그레이드

다음 명령은 실행 시점의 최신 안정 버전을 설치합니다. 이번 게시 검증 시점의 npm `latest`는 0.1.10입니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly set default
aptly --version
```

신규 키가 필요한 경우에만 `aptly set env OPENAI_API_KEY`를 실행하십시오. 기존 전역 설치는 관련 호스트·MCP·CLI 쓰기 프로세스를 중지하고 `aptly update` 후 `aptly setup --client all`로 등록을 확인하십시오. 기존 원장 전환·사용자 래퍼 보존 절차는 [설치 안내](../guide/ko.md#설치)를 따르십시오. 업데이트 후 MCP와 호스트를 재시작하고 새 Codex Hook이 있으면 신뢰를 검토하십시오. 통계 수집 활성화는 별도 선택입니다.

## 검증과 게시 상태

로컬 후보에서 테스트 612개(실패·생략 0), 타입 검사·빌드, fixture MCP(유료 호출·자식 실행 0), 공개 파일 검사(소스 290개·패키지 94개), 격리 tarball의 CLI·compiled exports·MCP·캐시와 4개 언어 문서 검사를 통과했습니다. compiled CLI는 0.1.10을 출력합니다. 준비 PR #123의 최종 HEAD 검사 19개와 정확한 병합 main CI 7개 성공을 구분해 확인했습니다. 검증은 합성 입력·격리 설치 기준이며 통계를 실제 사용자 호스트에 설치하거나 새로운 native·유료 시험을 수행한 결과로 표시하지 않습니다. 과거 별도 PoC와 이번 제품 검증도 구분합니다.

실제 [Actions 게시 실행](https://github.com/abruption/aptly/actions/runs/42768525205/attempts/1)의 설치 시험·새 runner 검증/pack·OIDC 게시 3개 job이 성공했습니다. artifact와 registry archive의 SHA-256·SHA-512 SRI 일치, npm 서명과 SLSA v1 인증서의 소스·태그·workflow·run/attempt identity를 확인했습니다. attestation 초기 404를 보존하고 같은 게시 실행의 6번째 조회에서 200을 확인했으며 태그·게시 job은 재실행하지 않았습니다. 전역 설치나 실제 호스트 설정은 변경하지 않았습니다. 상세는 [게시 근거](../releases/0.1.10.md)와 [배포 절차](../RELEASING.md)를 참고하십시오. 전체 변경은 [v0.1.9…v0.1.10](https://github.com/abruption/aptly/compare/v0.1.9...v0.1.10), 실제 패키지는 [aptly@0.1.10](https://www.npmjs.com/package/aptly/v/0.1.10)에서 확인하십시오.
