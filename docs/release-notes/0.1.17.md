# Aptly 0.1.17

복구 응답의 메타데이터 검증과 GitHub Release 링크 발행 절차를 보완합니다.

## 변경 사항

- **복구 응답 검사:** 재추천과 새 위임 준비에 같은 Zod 스키마를 적용합니다. 필수 인자, 이미 지정한 값, 호출 도구 또는 프로필이 서로 맞지 않으면 `recovery_metadata_invalid`를 반환합니다. `blocked` 응답에 적용할 인자가 들어 있는 경우도 같은 오류로 중단합니다. 완료된 분류는 다시 호출하지 않습니다. ([#180](https://github.com/abruption/aptly/issues/180), [PR #181](https://github.com/abruption/aptly/pull/181))
- **추천을 전달하는 방법:** 일반 재추천 응답에도 `required_fields`, `on_unavailable`, `next_action`이 들어갑니다. 적용할 수 없거나 판단이 어렵다면 중단하십시오. 기존 에이전트를 다시 쓴 경우는 추천 적용으로 보고하지 마십시오. 응답 전체를 검사하는 도구는 새 필드를 허용해야 합니다. 이 검사는 응답 형식을 확인하며, 호출자의 규칙 준수나 실행 권한, 실제 실행 여부는 확인하지 않습니다.
- **릴리즈 링크:** 저장소의 릴리즈 노트를 GitHub Release 본문으로 변환할 때 링크의 대상 파일과 문서 내 위치를 검사합니다. 가이드는 해당 버전의 태그에서 열리고, 태그를 만든 뒤 작성한 게시 기록은 파일이 있는 커밋에서 열립니다. 이 변환은 새 본문을 만들 때 사용합니다. ([#178](https://github.com/abruption/aptly/issues/178), [PR #179](https://github.com/abruption/aptly/pull/179))

## 업데이트

관련 호스트·MCP·CLI 프로세스를 중지한 뒤 전역 설치에서 실행하십시오.

```sh
aptly update
aptly setup --client all
```

MCP·호스트를 재시작하십시오. 키·정책·원장·통계는 초기화하지 않습니다. stable 실행기는 [보존 사본도 명시적으로 갱신](../guide/ko/configuration.md#guide-stable-launcher)하고 변경된 Codex Hook은 `/hooks`에서 승인하십시오. [설치·업데이트 안내](../guide/ko/installation.md#guide-package-updates)를 참고하십시오.

## 검증과 게시 상태

Rebut MCP의 Astra medium 코드 리뷰에서 차단 결함은 발견되지 않았습니다. 로컬 테스트 870개 중 854개 통과·실패 0개·임시 볼륨 조건으로 16개 제외와 타입·문서·패키지·fixture 검사를 확인했습니다. 정확한 main CI 7개와 Actions OIDC 게시 3개 job이 성공했으며, npm `latest` 0.1.17·배포 파일 일치·격리 설치·서명·provenance를 검증했습니다. 자세한 근거는 [게시 기록](../releases/0.1.17.md)을 참고하십시오. fixture는 실제 native 호출자의 추천 준수를 입증하지 않습니다.
