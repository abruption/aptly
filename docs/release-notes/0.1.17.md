# Aptly 0.1.17

복구 응답의 메타데이터 검증과 GitHub Release 링크 발행 절차를 보완합니다.

## 변경 사항

- **응답 정합성:** retry·fresh 적용 메타데이터를 공통 Zod 스키마로 검증합니다. 필수 인자·부분 pin·호출 도구·프로필 값의 불일치, blocked 상태의 적용 인자 등을 거절하며 `recovery_metadata_invalid`로 안전하게 중단합니다. 완료된 분류를 다시 호출하지 않습니다. ([#180](https://github.com/abruption/aptly/issues/180), [PR #181](https://github.com/abruption/aptly/pull/181))
- **적용 안내:** 일반 retry에도 `required_fields`, `on_unavailable`, `next_action`을 제공합니다. 금지·불명확 조건에서는 중단하며 기존 에이전트 재사용은 추천 적용 증거로 취급하지 않습니다. strict 응답 소비자는 추가 메타데이터를 허용해야 합니다. 이 검증은 호출자의 준수·권한·실제 실행을 보증하지 않습니다.
- **발행용 링크:** 파일용 노트를 발행용 본문으로 변환하고 파일·앵커를 검사합니다. 안내는 해당 태그, 태그 후 작성된 게시 기록은 파일이 있는 고정 커밋으로 연결합니다. 기존 Release 본문의 일괄 수정은 포함하지 않습니다. ([#178](https://github.com/abruption/aptly/issues/178), [PR #179](https://github.com/abruption/aptly/pull/179))

## 업데이트

관련 호스트·MCP·CLI 프로세스를 중지한 뒤 전역 설치에서 실행하십시오.

```sh
aptly update
aptly setup --client all
```

MCP·호스트를 재시작하십시오. 키·정책·원장·통계는 초기화하지 않습니다. stable 실행기는 [보존 사본도 명시적으로 갱신](../guide/ko/configuration.md#guide-stable-launcher)하고 변경된 Codex Hook은 `/hooks`에서 승인하십시오. [설치·업데이트 안내](../guide/ko/installation.md#guide-package-updates)를 참고하십시오.

## 검증과 게시 상태

Rebut MCP의 Astra medium 코드 리뷰에서 차단 결함은 발견되지 않았습니다. 로컬 테스트 870개 중 854개 통과·실패 0개·임시 볼륨 조건으로 16개 제외와 타입·문서·패키지·fixture 검사를 확인했습니다. 정확한 main CI 7개와 Actions OIDC 게시 3개 job이 성공했으며, npm `latest` 0.1.17·배포 파일 일치·격리 설치·서명·provenance를 검증했습니다. 자세한 근거는 [게시 기록](../releases/0.1.17.md)을 참고하십시오. fixture는 실제 native 호출자의 추천 준수를 입증하지 않습니다.
