`aptly@0.1.4` 릴리즈 준비 문서입니다. 아직 `v0.1.4` 태그와 npm 패키지를 게시하지 않았으며, 실제 게시 파일·서명·provenance 검증은 게시 후 별도로 진행합니다.

## 주요 변경

- **모든 지원 대상 호출의 사전 검사:** 설치된 native `PreToolUse` Hook은 일치하는 서브에이전트 호출을 로컬 Aptly MCP로 전달합니다. Codex의 `fork_turns: "all"`이나 fork 생략도 추천을 평가하고, 부분적으로 지정된 모델·effort는 일치하는 허용 프로필로 후보를 제한해 미지정 필드만 선택합니다. 호스트의 Hook 로드·신뢰·MCP 연결이 필요하며 미설정·미지원 호스트까지 서버가 가로채도록 강제하지는 않습니다.
- **짧은 작업명 처리:** 암호화된 Codex 본문은 해독·전송하지 않습니다. `cleanup_merged_worktrees` 같은 구체적인 작업명은 제한된 action/scope/object 허용 목록으로 분류할 수 있으며, 다른 이름에는 기존 구체성·크기·민감 패턴 검사를 유지합니다. 작업명만으로 정보가 충분하다는 보장은 없고 `needs_context`는 계속 유효한 보류 결과입니다.
- **호출별 진단:** `get_spawn_routing_observation`으로 사전 검사·분류/캐시 결과·추천·인자 출력 또는 적용 차단을 구분합니다. 프로세스 공용 마지막 결과를 다른 세션의 증거로 사용하는 대신 정확한 원본 호출을 조회합니다. 실제 자식 실행은 별도 관측 대상입니다.
- **명시적 설명 전달:** `prepare_spawn_context`로 예정된 호출에 짧은 작업 설명을 등록하고 `cancel_spawn_context`로 취소할 수 있습니다. 같은 MCP 프로세스에 실제 호출 ID와 정확한 원본 이벤트를 제공할 수 있는 호출자용 경로입니다. 설명은 정책·권한·검증된 사용자 의도가 아닌 신뢰하지 않는 작업 데이터로 처리합니다.

## 적용 범위와 호환성

**상속 호출을 추천하는 것과 자식 모델을 실제로 변경하는 것은 다릅니다.** 제품의 Codex 인자 변경은 계속 명시적 `fork_turns: "none"`에 한정합니다. `all`·생략 호출은 `inherited_context_application_unverified`로 적용을 차단하고 이력을 보존합니다. Claude Code도 이력 제약이 없는 일반 호출에서만 적용합니다. 고정 역할·resume·명시 필드·승인·샌드박스·MCP 권한은 유지하며 `all`을 자동으로 `none`으로 바꾸지 않습니다. 입력 필드만으로 선택의 출처를 확인했다고 주장하지 않습니다.

이번 버전에서는 `get_routing_capabilities.automatic_hook.last_result`가 **제거됩니다**. 기존 진단 도구나 스크립트는 동일한 `client`와 원래 Hook `event`를 사용해 `get_spawn_routing_observation`을 호출하도록 전환하십시오. 기록은 현재 MCP 프로세스의 최근 128개·10분 범위이며, 다른 프로세스·재시작·만료·퇴출·입력 불일치로도 `not_observed`가 나올 수 있습니다. 이는 전체 호스트가 Hook을 우회했다는 증거가 아닙니다. `arguments_updated`도 호스트가 인자를 수용했거나 자식이 해당 모델로 실행됐다는 증거가 아니며 `execution`은 계속 `not_observed`입니다.

설명 연결은 5분 뒤 만료되고, 프로세스당 128개 한도에서 취소·만료 tombstone을 유지합니다. 중복 등록으로 만료를 연장하거나 다른 입력에 다시 연결하지 않습니다. 설명 해시를 영속 입력·정책·후보 결합에 포함하고, 변경·만료·취소·불일치 시 적용을 중단합니다. 이미 시작한 유료 요청의 결과가 불명확하면 새 ID나 새 설명으로 자동 재시도하지 않습니다.

**기본 Hook은 설명을 자동 생성하거나 미래 native 호출 ID를 배정하지 않습니다.** 정확한 이벤트를 사전에 확보하지 못하거나 다른 MCP 프로세스에 연결하는 경로에는 이 설명 전달을 사용할 수 없습니다. 부모 에이전트가 임의의 ID나 지원하지 않는 spawn 필드를 만들어 연결할 수는 없습니다. [설명 전달 계약](https://github.com/abruption/aptly/blob/main/docs/SPAWN_CONTEXT.md)에서 지원 호출자와 실패 경계를 확인하십시오.

명시적으로 등록한 설명은 원래 라벨·본문 대신 작업 텍스트로 전달합니다. 기존 client·후보 설명 등 제공자 계약도 전송되지만 암호문·이력·파일·원시 오류를 추가하거나 URL을 자동 조회하지 않습니다. 상속·부분 지정 호출도 적용 가능 여부와 관계없이 제한된 작업 요약을 전송할 수 있으므로 이력 상속을 공유 거부 설정으로 사용하지 마십시오. 자동 정책의 `enabled: false`가 공유 거부 경로이며, 알려진 민감 패턴 검사는 완전한 비밀 탐지나 익명화를 보장하지 않습니다.

## 설치와 업그레이드

기존 원장에 접근하는 관련 호스트·MCP·CLI writer를 먼저 중지하십시오. JSON 원장·`unknown`·비용·완료 캐시와 유효한 SQLite gate·journal은 보존하십시오. 0.1.2 이전 버전에서 전환한다면 [설치·원장 전환 안내](https://github.com/abruption/aptly/blob/main/docs/guide/ko.md#설치)의 오프라인 절차를 확인하십시오. 0.1.3에서 이번 버전으로 바꾼다는 이유로 원장이나 잠금 파일을 초기화할 필요는 없습니다.

**다음 명령은 0.1.4 게시 후 사용하십시오.** 게시 전 `@latest`는 이전 안정 버전을 가리킬 수 있습니다. 0.1.3 이상을 사용하는 검증 가능한 전역 npm 설치에서는 같은 prefix를 갱신할 수 있습니다.

```sh
aptly update
aptly setup --client all --mode defaults
aptly --version
```

`aptly update`는 설치 스크립트를 실행하지 않으므로 명시적 `setup`과 호스트·MCP 재시작이 필요합니다. 기존 MCP 실행 경로·사용자 래퍼를 자동 이전하거나 API 키를 다시 저장하지 않습니다. 로컬 설치·확인할 수 없는 경로에서는 수동 설치 안내를 사용하십시오.

새 설치나 npm을 통한 수동 업그레이드는 다음과 같습니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly setup --client all --mode defaults
aptly --version
```

옵션을 지원하지 않는 npm에서는 `npm install -g aptly@latest --ignore-scripts` 후 명시적으로 `setup`을 실행하십시오. API 키 설정은 기존 OS 자격 저장소 경로를 사용하며 키를 명령행·설정 파일·저장소에 기록하지 마십시오. 재시작 후 새 MCP 도구 목록과 Hook 상태를 확인하고, Codex의 새 Hook 검토나 신뢰 승인이 필요한 경우 `/hooks`에서 진행하십시오. 이번 릴리즈 준비는 사용자의 실제 설치·호스트 설정·키·운영 원장을 변경하지 않습니다.

## 검증 근거와 한계

통합 소스의 기준 회귀 테스트 432개와 76개 npm 파일 기준은 준비 PR에서 최종 후보로 다시 검증합니다. 타입·빌드·공개 파일 검사·설치한 compiled CLI/MCP/cache smoke·다국어 문서·원격 CI의 실제 결과는 해당 PR에 기록합니다. 준비 검증을 실제 npm 게시나 새 provenance 검증으로 대신하지 않습니다.

이전 단계의 제한된 native 시험은 다음 사실을 구분해 확인했습니다.

- **PR #60 원본:** 맥미니 Codex CLI 0.167.0에서 실제 Hook → MCP → Decisions 요청 1회가 진행됐습니다. 짧은 작업명만으로는 제공자가 `needs_context`를 선택했고, 자식은 부모의 Sol/low를 유지했습니다. 제공자의 구체적인 판단 이유를 응답에서 확인한 것은 아닙니다.
- **별도 호스트 수용 시험:** 검증용 Hook 응답 어댑터로 `fork_turns: "all"`을 유지하며 자식 Terra/high 실행과 부모 이력 복사를 관측했습니다. 이는 해당 런타임의 Hook 인자 변경 수용 근거이며 제품 적용 성공이 아닙니다. 제품의 상속 적용 guard는 그대로입니다.
- **PR #62 설명 전달 시험:** 검증용 전송 어댑터가 실제 이벤트를 받아 같은 MCP 프로세스에 안전한 합성 설명을 등록한 뒤 원본 Hook 요청을 전달했습니다. 실제 Decisions 요청 1회에는 라벨이 붙은 설명만 작업 텍스트로 전송됐고, `codex-simple`인 Luna/max가 추천됐습니다. 상속 적용은 차단돼 실제 자식은 부모 Sol/low를 유지했습니다. 호출 연결·설명 전송·이력 복사와 마지막 자식 응답을 별도로 대조했습니다.

이 관측은 제한된 명시적 프로토콜·호스트 수용 검증입니다. 설명 보강의 인과 효과·추천 품질·모든 기기나 Codex 버전의 지원·전체 작업 비용 절감을 입증하지 않습니다. 기본 Hook의 자동 설명 생성기나 일반 사용자 경로가 제공된다는 뜻도 아닙니다. 이번 0.1.4 준비에서 새 유료 분류·native 에이전트 시험을 실행했다고 주장하지 않습니다.

게시 요청은 받은 상태이며, 준비 PR 병합과 해당 main CI 성공 후 `v0.1.4` 태그를 push하면 Actions OIDC 게시가 시작됩니다. 실제 게시 후에는 그 실행이 새로 만든 artifact와 registry 파일, npm 서명·SLSA bundle 및 인증서의 소스·태그·workflow·실행 identity를 다시 검증해야 합니다. 과거 버전의 digest·실행 번호·성공 결과는 재사용하지 않습니다.
