# Aptly 0.1.5

**게시 전 릴리즈 노트 초안입니다.** 준비 PR 병합·main CI 확인과 별도 게시 지시가 남아 있습니다. 태그·npm 게시·이번 버전의 서명 및 provenance 검증은 아직 수행하지 않았습니다.

## 주요 변경

Aptly 0.1.5는 작업 맥락이 부족할 때 설명을 한 번 보충해 추천을 이어가는 경로와, 추천 실패·적용 불가를 분명하게 알리는 동작을 추가합니다.

- **맥락 보충 후 재추천:** Hook이 `insufficient_context` 또는 `provider_needs_context`를 반환하면 부모 에이전트에 복구 ID와 안내를 제공합니다. 부모는 같은 MCP 프로세스에서 5분 안에 `retry_spawn_recommendation({retry_id, description})`으로 목적·범위·결과물을 보충할 수 있습니다. 미래 native 호출 ID를 만들 필요는 없습니다.
- **호환 기본값 전달:** 추천 응답의 `next_call.set_if_unspecified`에 다음 호출에서 채울 필드만 제공합니다. 기존 명시 선택을 덮어쓰지 않고 Claude에는 effort를 추가하지 않습니다. `context_retry_allowed: false`는 추가 설명 보충의 종료이며, 호스트 실행이나 권한 승인을 뜻하지 않습니다.
- **조용한 기본 모델 실행 방지:** 유효하고 활성화된 `defaults` 경로의 적용 불가·분류 실패·예산 초과·결과 불명은 `deny`와 안전한 사유로 알립니다. 이 경우 기존 모델로 계속 실행하던 경로가 중단될 수 있습니다. `advisory`는 차단 없이 안내하며, 정책 미설정·비활성화, 명시 튜플·고정 역할·resume은 의도적인 로컬 보존 경로로 유지합니다.
- **복구 관측 개선:** `get_spawn_routing_observation`은 정확한 `{client,event}` 또는 `{retry_id}` 중 하나를 받습니다. 원래 사전 검사와 `context_retry.outcome`, 최근 거절인 `last_attempt`를 구분합니다. 입력 스키마 노출과 같은 이벤트 재처리 시 관측 보존도 보완합니다.
- **빠른 시작 정비:** README 4개 언어에 최초 키 설정을 명시하고 설치와 업데이트를 분리합니다. 기본 설치는 계속 `aptly@latest`를 사용합니다.

보충은 원래 호출당 한 번입니다. 고정 요청 ID·설명 해시·중복 캐시·예산·결과 불명·취소·만료 보호를 유지합니다. 암호문을 해독하거나 이력·파일을 추가 전송하지 않으며, 설명에 적은 URL을 자동 조회하지 않습니다.

## 설치와 업데이트

기존 영속 원장에 접근하는 호스트·MCP·CLI writer를 먼저 중지하십시오. JSON 원장·완료 캐시·`unknown`·비용 기록과 유효한 SQLite gate·journal을 보존하십시오. 0.1.2 이전 버전에서는 [설치·원장 전환 안내](../guide/ko.md#설치)의 오프라인 절차를 확인하십시오. 이번 버전으로 바꾼다는 이유로 원장이나 잠금 파일을 초기화하지 마십시오.

다음 명령은 게시 후 최신 안정 버전을 설치합니다. 0.1.3 이상을 사용하는 검증 가능한 전역 npm 설치에서는 다음 순서로 업데이트할 수 있습니다.

```sh
aptly update
aptly setup --client all --mode defaults
aptly --version
```

`aptly update`는 설치 스크립트를 실행하지 않으므로 명시적 `setup`과 호스트·MCP 재시작이 필요합니다. 기존 실행 경로·사용자 래퍼를 자동 이전하거나 API 키를 다시 저장하지 않습니다. 현재 모드와 다른 설정을 적용하려면 [설치 안내](../guide/ko.md#설치)를 먼저 확인하십시오.

새 설치는 다음과 같습니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly setup --client all --mode defaults
aptly set env OPENAI_API_KEY
aptly --version
```

기존 키가 설정된 수동 업그레이드에서는 키를 다시 입력할 필요가 없습니다. 옵션 미지원 npm은 `--ignore-scripts` 설치 후 명시적 `setup` 절차를 사용하십시오. 재시작 후 새 MCP 도구와 Hook 상태를 확인하고, Codex에서 새 Hook 검토·신뢰 승인이 필요하면 `/hooks`에서 진행하십시오.

## 검증과 지원 범위

기능 개발 단계에서 회귀 테스트 453개와 제한된 native 시험을 수행했습니다. [전달·복구 계약](../SPAWN_CONTEXT.md)에 시험 조건과 실패 이력을 구분해 기록합니다.

- Codex 0.167.0에서는 별도 복구 순서를 지시하지 않은 fork 생략 호출이 Hook 차단·부모의 맥락 보충·Decisions 추천까지 진행됐습니다. 상속 적용은 미검증이므로 부모가 제약을 보고하고 자식은 생성하지 않았습니다.
- Claude Code 2.1.314에서는 초기 생략이 모델 고정이 아님을 명시한 위임 요청으로 복구 후 Haiku를 추천받았습니다. 다음 Agent 호출의 `model: haiku`, 실제 자식 `claude-haiku-5-5`, 올바른 결과를 확인했습니다. 복구 도구명이나 호출 순서는 프롬프트에 제공하지 않았습니다.

이 결과는 대표 조건의 호출자 주도 복구 시험입니다. 모든 부모 모델의 후속 호출을 보장하지 않으며, 상속 모델 적용·추천 품질·일반 비용 절감·모든 호스트 지원을 검증한 것은 아닙니다. 과거 제한된 비용 실측의 조건과 수치는 변경하지 않습니다.

보장은 활성화·신뢰·연결 상태의 지원 Hook이 실제 호출된 범위입니다. Hook 미등록·미신뢰·연결 실패·호스트 오류를 MCP 서버가 강제로 가로챌 수는 없습니다. 관측 조회는 유료 요청을 만들지 않으며 서버의 실행 상태는 계속 `not_observed`입니다. 추천·인자 출력·실제 실행을 서로 구분하십시오.

릴리즈 준비에서는 새 유료 분류·native 시험·운영 설치·자격정보 변경을 수행하지 않습니다. 준비 검증과 실제 게시 파일·서명·provenance 검증은 별도 단계입니다. 실제 게시 후 새 source SHA·태그·Actions run·artifact digest와 검증 결과를 기록해야 합니다. [배포 절차](../RELEASING.md)를 참고하십시오.
