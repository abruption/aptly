# Aptly 0.1.12 — 핫픽스 준비

0.1.11의 `codex-home` 전환 후 일반 터미널에서 설정 명령이 실패하는 문제를 수정하는 후보입니다. 아직 npm에 게시하지 않았습니다.

## 수정 사항

[#135](https://github.com/abruption/aptly/issues/135)·[PR #136](https://github.com/abruption/aptly/pull/136): `CODEX_HOME`이 없는 터미널에서 `aptly setup`이 `policy_source_home_invalid`로 실패하던 경로를 수정합니다. CLI가 이미 선택한 표준 `~/.codex`를 정책 참조 검증에 사용합니다. 이제 해당 경로에서 setup이 성공하면 `aptly setup && aptly set transmission --review`의 검토 단계로 진행할 수 있습니다. 전송 범위를 자동 선택하거나 동의 완료로 표시하지 않습니다.

명시한 계정 홈은 유지하며 빈 값·상대 경로·제어문자는 거부합니다. 실행 중 MCP 서버에서 `CODEX_HOME`이 전달되지 않았을 때 다른 홈으로 추정하지 않고 중단하는 검사는 유지합니다. CLI의 기본 홈 선택은 실행 중 호스트의 전체 설정을 인증하지 않습니다.

기존 키·정책 내용·전송 범위·원장·통계·Hook 신뢰와 고정/공유 정책 참조는 보존합니다. 0.1.11의 배포 근거는 [게시 기록](../releases/0.1.11.md)에 별도로 남깁니다.

## 설치와 검증

게시 후 `npm install -g aptly@latest --allow-scripts=aptly` 또는 검증된 전역 설치의 `aptly update`로 갱신하고, 의도한 홈에서 설정을 확인한 뒤 MCP를 재시작하십시오. 0.1.11을 사용하는 동안에는 기본 홈 CLI에 `CODEX_HOME="$HOME/.codex"`를 명시할 수 있습니다. 계정별 홈이 필요한 경우 해당 계정의 절대 경로를 사용하십시오.

668개 회귀 테스트와 두 Mac의 격리 설치에서 기본 홈의 compiled CLI 실행, 정책 보존과 MCP 홈 누락 차단을 확인했습니다. 빌드·문서·공개 패키지·설치 tarball 검증을 수행했으며 유료 API 호출이나 native 자식 실행 시험이 아닙니다. 실제 게시와 호스트 갱신 결과는 [준비 기록](../releases/0.1.12.md)에 후속으로 기록합니다.
