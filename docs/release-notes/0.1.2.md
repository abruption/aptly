2026-11-06에 `aptly@0.1.2`를 GitHub Actions OIDC로 게시하고 registry 파일과 provenance를 검증했습니다.

## 주요 변경

- 키 입력·저장 전에 `--check`로 실행 경로를 진단하고, 소유권 기록과 일치하는 표준 등록만 명시적으로 갱신할 수 있습니다. 초기 진단이 실패하면 CLI는 모든 대상의 설정을 유지합니다.
- 영속 원장의 잠금을 Node.js 내장 SQLite의 프로세스 수명 잠금으로 전환했습니다. 강제 종료 후에도 기존 `unknown`·비용 예약·완료 캐시를 보존하며 새 요청 처리를 재개합니다.
- 분류 요청의 task 필드를 명시적으로 제한하고 전송·비활성화·필터 한계를 문서화했습니다. 기본 공유 방식이나 confidence 기준을 변경한 릴리즈는 아닙니다.
- 일반 설치는 `npm install -g aptly@latest`로 안내하며, 부제에 OpenAI Decisions API 사용을 명시했습니다.

## 업그레이드 전 확인

1. **기존 영속 원장에 접근하는 모든 호스트·MCP·CLI writer를 중지하고 함께 업그레이드하십시오.** 구버전 writer와 새 영구 SQLite `.lock`의 혼합 운영은 지원하지 않습니다.
2. 새 잠금 파일은 정상 종료 후에도 남습니다. 유효한 gate·journal을 삭제하지 마십시오. 기존 빈/미확인 잠금은 자동 복구하지 않으며, 확인된 legacy 잠금만 오프라인으로 격리합니다. JSON 원장·`unknown`·비용·완료 캐시는 초기화하지 않습니다. 새 설치에는 legacy 격리가 필요하지 않습니다.
3. 실행 경로 오류는 키를 다시 입력하기 전에 진단하십시오. 사용자 지정 래퍼나 변경된 소유권 기록은 명시적 이전에서도 거절하며 검사를 우회해 채택하지 않습니다.

```sh
aptly set env OPENAI_API_KEY --client claude --check
aptly setup --client claude --migrate-launcher --dry-run
```

[0.1.2 설치·이전 안내](https://github.com/abruption/aptly/blob/v0.1.2/docs/guide/ko.md#설치)에서 실제 적용 조건을 확인하십시오. 원자적 hard link와 SQLite 잠금을 지원하는 로컬 파일시스템 및 하나의 정규 원장 경로를 전제로 합니다.

## 배포와 검증

[Actions 실행 42151554506 / attempt 1](https://github.com/abruption/aptly/actions/runs/42151554506/attempts/1)의 설치 시험·새 runner 패키징·OIDC 게시가 모두 성공했습니다. 게시 전 테스트 371개와 플랫폼 CI를 통과했고, 게시 후 새 artifact와 registry 파일의 무결성, npm 서명·정확한 SLSA bundle, 인증서의 소스·태그·workflow·실행 identity를 검증했습니다.

Windows CI는 PowerShell을 사전 구동하고 테스트 파일을 직렬 실행하되 실제 다중 프로세스 경쟁 검사와 제품의 ACL 검증·제한 시간은 유지합니다. 합성 시험·게시 검증은 모델 품질이나 모든 호스트 환경의 동작을 인증하지 않으며, 이번 게시 작업에서 실제 운영 원장을 이전하지 않았습니다.
