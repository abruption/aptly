# Aptly 0.1.8

릴리즈 준비 중입니다. 아직 `v0.1.8` 태그·npm 게시·GitHub Release를 생성하지 않았습니다. 준비 검사와 실제 게시 파일·서명·provenance 검증은 별개입니다.

## 주요 변경

Aptly 0.1.8은 로컬 분류 예산을 운영자가 설정하고 확인하는 경로를 추가합니다. 명령·하위 명령의 도움말도 실행 부작용 없이 통일합니다. 명시한 모델·effort·역할·필수 이력·권한과 기존 차단은 보존합니다.

### 로컬 예산 설정과 복구

| 환경변수 | 새 기본값 | 의미 |
|---|---:|---|
| `APTLY_MAX_DAILY_CALLS` | `200` | 원장별 UTC 일일 분류 시도 상한 |
| `APTLY_MAX_TOTAL_CALLS` | `0` | 원장별 누적 분류 시도 상한 |
| `APTLY_MAX_ESTIMATED_USD` | `0` | 누적 로컬 비용 예약액 상한 |
| `APTLY_ESTIMATED_CALL_USD` | `0.002` | 새 분류 시도마다 예약할 추정 달러 금액 |

세 상한의 **정확한 문자열 `0`은 무제한**입니다. 회당 예약 단가는 상한이 아니므로 양수여야 합니다. `0.0` 같은 모호한 0 표기·음수·비정상/지수 표기·예산 변수 오타는 거절합니다. 금액은 소수점 이하 최대 6자리, 호출 수는 정수입니다. 이 값은 실제 OpenAI 청구액이나 계정 전체 지출 상한이 아닙니다.

- `aptly set env`로 네 변수를 설정하고 `aptly set default`로 누락된 기본값만 채웁니다. 명시 값·0·Codex `env_vars` 전달 선언·CLI 환경에서 관찰된 Claude 상속값은 보존합니다. 키·원장·사용량·캐시를 리셋하지 않습니다. 오류에는 알려진 변수명과 고정 사유만 표시하며 실제 입력값은 노출하지 않습니다.
- `aptly budget status`는 설정·허용된 현재 환경의 스냅샷과 사용량·잔여량·소진 항목을 보여 줍니다. 키·provider 조회, 설정 쓰기, 원장/gate 초기화, chmod는 하지 않습니다. 기존 gate는 잠시 취득하므로 경합 시 `ledger_locked`가 발생할 수 있습니다. 실행 중인 호스트나 사용자 래퍼의 전체 환경을 인증하지 않습니다.
- 새 HTTP 전 예산 거절은 캐시하지 않습니다. 검증 가능한 기존 기본 정책의 미지불 `budget_exhausted` 결과만 같은 ID로 다시 평가합니다. 이미 완료된 provider 결과와 `unknown`은 재실행하거나 삭제하지 않으며 단가 변경·키 재입력으로 과거 예약을 환불·재계산하지 않습니다.
- 런타임의 네 예산 값만 레거시 0.1.7 digest와 호환되게 처리합니다. 임의의 커스텀 라이브러리 정책은 기존 전체 hash를 유지하며 과거 설정을 추측하지 않습니다. 불명 결과나 결합 충돌을 새 유료 ID·원장 삭제로 우회하지 않습니다. 월간 자동 창·리셋/리필 CLI는 추가하지 않습니다.

### 통일된 명령 도움말

루트와 17개 명령/하위 경로에서 `--help`·`-h`·`aptly help <경로>`를 지원합니다. 운영 처리 전에 도움말을 결정하므로 stdin·설정/지정 파일·자격 저장소를 읽거나 질문·설정 변경·API/모델 정보 조회·설치/갱신·업데이트 알림을 실행하지 않습니다. 필수 인자를 생략해 사용법을 조회할 수 있지만 제공한 값·옵션·순서·명시적 모순·공백으로 묶인 복합 명령 토큰은 검증합니다. 잘못된 도움말은 인자를 반향하지 않는 고정 오류와 종료 코드 2로 응답합니다. 인자 없는 stdio serve 및 정상 명령의 출력 형식은 유지합니다.

```sh
aptly set default --help
aptly set env OPENAI_API_KEY -h
aptly budget status --help
aptly help catalog refresh
```

## 설치와 업그레이드

아래는 **0.1.8 게시 후** 최신 안정 버전을 설치하는 명령입니다. 게시 전 `latest`는 0.1.7일 수 있습니다. Node.js 24 이상이 필요합니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly set default
aptly set env OPENAI_API_KEY
aptly --version
```

기존 전역 설치는 관련 호스트·MCP·CLI writer를 먼저 중지한 뒤 갱신하십시오. 원장·완료 캐시·`unknown`·비용 기록과 유효한 SQLite gate/journal을 보존합니다. 0.1.2 이전 버전의 원장 전환은 [설치 안내](../guide/ko.md#설치)의 오프라인 절차를 따르십시오.

```sh
aptly update
aptly set default
aptly budget status
aptly --version
```

**예산 변수가 없는 등록이 0.1.8 런타임으로 실행되면 새 기본값을 사용합니다.** 이전의 암묵적 20회/50회/$0.50 제한은 유지되지 않습니다. 특정 상한이 필요하면 네 환경변수를 명시적으로 설정하십시오. 상태의 무제한은 `Unlimited`, 잔여 한도는 `null`입니다. 이는 금액 환불·사용량 초기화가 아니며 여러 세션이 같은 원장을 쓰면 예산을 공유합니다.

예산 설정 변경 후 MCP를 재시작하십시오. 기존 실행 경로·사용자 래퍼와 키는 자동 이전하지 않습니다. CLI의 0.1.8 출력만으로 등록된 MCP 서버의 업그레이드까지 인증하지 않습니다. 이전 경로가 남으면 설치 안내에 따라 전환하고, 재시작한 MCP의 `get_routing_capabilities`에서 `budget_configuration`을 확인하십시오. Codex가 새 Hook 신뢰 검토를 요구하면 `/hooks`에서 진행합니다. 기존 키를 다시 입력할 필요는 없습니다.

예산 회복은 기존 문맥 보충 참조의 5분 만료나 프로세스 수명을 연장하지 않습니다. 재시작 전 참조를 새 프로세스에서 재사용할 수 없으며 필수 이력·권한 제약도 해제되지 않습니다.

## 검증 경계와 게시 절차

기능 개발 단계에서는 통합 테스트 536개·도움말 매트릭스·실제 터미널 도움말·mock provider와 프로세스 간 동일-ID 복구 등을 검증했습니다. 이것은 새 릴리즈 후보 검사나 실제 API/native 품질 평가를 대신하지 않습니다. Claude Code·Antigravity의 자료 기반 검수 지적을 반영했으며 마지막 최소 수정의 로컬 검증과 검수 모델의 직접 시험을 구분합니다.

이번 준비 후보에서 536개 테스트(실패·생략 0)·타입/빌드·fixture PoC·설치 tarball CLI/compiled exports/MCP/cache·4언어 문서·릴리스 검사(소스 259개·패키지 84개)가 통과했습니다. compiled CLI는 0.1.8을 출력합니다. 정확한 PR HEAD의 원격 CI와 실제 게시 검증은 별도로 확인합니다. 실제 OpenAI 청구액, 자식 작업 품질, 보편적 호스트 적용이나 전체 비용 절감을 새로 입증하지 않습니다. 추가 제품 유료/native 평가·전역 설치·실제 설정/키/원장 변경·예산 리셋은 수행하지 않습니다. 준비 검수용 서브에이전트 선택의 Aptly 추천과 검수 오케스트레이션은 기존 분류 파일럿이나 비용에 합산하지 않습니다.

준비 PR 병합과 정확한 main CI 성공 후 별도 게시 지시에 따라 태그를 생성합니다. 태그 push는 실제 Actions OIDC 게시를 시작하며, 실제 registry 파일·서명·provenance는 새 실행에서 검증합니다. 현재는 아직 게시 완료 상태가 아닙니다. [배포 절차](../RELEASING.md)를 참고하십시오.
