# Aptly 0.1.9

2026-11-09에 #107·#108·#110과 준비 PR #115를 병합한 소스 `0b77bec4ecf402ccf3d6bd278499631bd12d76c0`의 `v0.1.9` 태그로 Actions OIDC 게시를 완료했습니다. npm `latest`는 0.1.9로 확인했습니다. 준비는 [#111](https://github.com/abruption/aptly/issues/111), 게시 기록은 [#118](https://github.com/abruption/aptly/issues/118)과 [실제 게시 근거](../releases/0.1.9.md)에서 관리합니다. npm 서명·인증서 기반 provenance를 검증했으며 [정식 Latest GitHub Release](https://github.com/abruption/aptly/releases/tag/v0.1.9)의 공개 시각은 `2026-11-09T11:44:09Z`입니다.

## 주요 변경

Aptly 0.1.9는 Linux 자격 저장소의 준비 상태와 다른 호스트 홈을 참조하는 등록의 복구 진단을 개선합니다. 저장소의 의존성·비밀정보 검사도 추가합니다.

### Linux 자격 저장소 사전 진단

`OPENAI_API_KEY` 설정 전에 실행 가능한 `secret-tool`과 확인 가능한 세션 버스·Secret Service 메타데이터를 검사합니다. 다음 명령은 키 입력이나 저장 없이 선택한 호스트를 진단합니다.

```sh
aptly set env OPENAI_API_KEY --client all --check
```

확실한 도구·버스·서비스 부재는 `secure_store_unavailable`과 구체적인 코드로 알립니다. 버스 접근 또는 탐색 도구가 확인되지 않으면 준비 상태 미확인으로 구분합니다. 서비스가 존재하거나 활성화 가능하다는 결과만으로 잠금 해제·키 읽기·쓰기를 보장하지 않습니다.

진단은 패키지를 자동 설치하거나 Secret Service를 활성화·잠금 해제하지 않습니다. 필요한 구성 요소는 운영자가 설치하고 사용할 데스크톱 세션에서 확인하십시오. 실제 키 저장은 여전히 실패할 수 있습니다.

SSH·헤드리스 환경에서는 `APTLY_SECRET_BACKEND`가 없는 경우 호스트 MCP 프로세스에 `OPENAI_API_KEY`를 안전하게 전달하십시오. 기존 인증 래퍼와 환경은 보존합니다. OS 저장소를 명시한 등록에서 환경변수 인증으로 조용히 대체하지 않습니다.

### 호스트 홈 불일치와 읽기 전용 설정 확인

다른 호스트 홈의 정책을 참조하는 등록은 `hook_policy_path_conflict`와 로컬 복구 안내로 진단합니다. 선택된 호스트 설정 디렉터리와 기존 정책 참조를 확인하고 의도한 디렉터리를 선택하십시오. 정책·키·원장·신뢰 설정을 복사하거나 실행기 이전으로 불일치를 우회하지 마십시오.

```sh
aptly setup --check --client all
```

`setup --check`는 일반 설정 계획을 읽기만 하며 파일·디렉터리를 생성하지 않습니다. 함께 지정할 수 있는 옵션은 `--client`뿐이며 실행 중인 호스트를 검증하지 않는 시점별 확인입니다. `--check` 실행은 업데이트 알림을 위한 registry 조회나 알림 캐시 생성도 하지 않습니다.

### 저장소 보안 검사

Dependabot의 주간 npm·GitHub Actions 업데이트, 전체·런타임 의존성의 high 이상 취약점 검사, 해시를 고정한 Gitleaks의 Git 이력 검사를 추가합니다. 비밀정보 탐지 결과는 마스킹합니다.

같은 저장소의 인증된 Dependabot이 허용된 의존성 파일만 변경할 때 선행 Issue 요건을 면제합니다. 불완전하거나 허용 범위를 벗어난 변경 목록은 거절합니다. npm·Actions 업데이트 모두 정책에 맞는 범위 포함 제목을 생성하며, 일반 리뷰·필수 CI·별도 병합 승인 요건을 유지합니다.

## 설치와 업그레이드

Node.js 24 이상이 필요합니다. 아래 명령은 실행 시점의 최신 안정 버전을 설치합니다. 게시 검증 시점의 npm `latest`는 0.1.9입니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly set default
aptly --version
```

지원하지 않는 npm의 대체 절차는 [설치 안내](../guide/ko.md#설치)를 따르십시오. 신규 키 설정이 필요한 경우에만 `aptly set env OPENAI_API_KEY`를 실행하십시오. 기존 키를 다시 입력할 필요는 없습니다.

기존 전역 설치는 관련 호스트·MCP·CLI 쓰기 프로세스를 중지한 뒤 `aptly update`로 갱신하십시오. 기존 실행 경로·사용자 래퍼·인증 환경과 원장·완료 캐시·불명 결과·비용 기록을 보존하고, 등록 상태는 위의 `setup --check`로 확인하십시오.

갱신 후 호스트와 MCP를 재시작하십시오. Codex가 새 Hook의 신뢰 검토를 요구하면 `/hooks`에서 검토하고 승인하십시오. CLI 버전 출력만으로 실행 중인 MCP의 갱신이나 호스트 적용까지 확인하지 않습니다.

## 검증 경계와 게시 절차

통합 후보에서 테스트 556개(실패·생략 0), 타입 검사·빌드, fixture MCP, 4개 언어 문서 검사, 공개 범위 검사(소스 270개·패키지 86개), 격리 tarball의 CLI·compiled exports·MCP·캐시 검증이 통과했습니다. compiled CLI는 0.1.9를 출력합니다. 준비 PR #115의 최종 HEAD 검사 19개와 병합 main CI 7개가 성공했습니다. Linux 메타데이터 진단이나 fixture·CI 성공은 실제 자격 저장소 쓰기, 사용자 호스트의 native 실행 또는 API 품질을 보증하지 않습니다.

별도 사용자 지시 후 annotated 태그와 [Actions OIDC 게시 실행](https://github.com/abruption/aptly/actions/runs/42610755012/attempts/1)의 3개 job 성공을 확인했습니다. 이번 artifact와 registry archive의 SHA-256이 일치했습니다. npm 서명·인증서 기반 provenance의 소스·태그·workflow·run/attempt 결합과 정식 Latest GitHub Release를 확인했습니다. attestation 초기 404 이후 7번째 조회의 200을 확인한 뒤 검증했으며 태그·게시 job은 재실행하지 않았습니다. 이전 버전의 검증 결과를 재사용하지 않았습니다. Dependabot PR #112·#113·#114·#116·#117은 이 릴리스에 포함하지 않았습니다. 자세한 소스·태그·workflow·registry 근거는 [게시 기록](../releases/0.1.9.md)과 [배포 절차](../RELEASING.md)를 참고하십시오.
