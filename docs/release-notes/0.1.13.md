# Aptly 0.1.13

설정 상속과 읽기 전용 진단을 개선하고 조회 오류를 명확하게 보고합니다. 이 문서는 출시 준비용이며 태그·npm 게시 완료를 뜻하지 않습니다.

## 변경 사항

- 모델 후보 상속: `aptly set default`가 Codex의 전달 선언과 Claude의 관측된 상속 환경에 있는 후보 및 별칭을 보존합니다. Codex 전달 값이 현재 CLI에서 보이지 않아도 기본 후보로 덮어쓰지 않습니다. 명시적 등록 값과 기존 실행기는 유지합니다. ([#140](https://github.com/abruption/aptly/issues/140), [PR #145](https://github.com/abruption/aptly/pull/145))
- 조회 상태와 종료 코드: `aptly stats [--today]`와 `aptly set transmission --show`에 최상위 `status`를 추가합니다. 조회 완료는 `complete`/종료 코드 0, 확인된 오류는 `partial`/종료 코드 1입니다. 정상 미설정·비활성도 조회 완료이며 호스트 준비 상태를 보증하지 않습니다. 정책 경로 충돌과 통계 소유권이 남은 설정 유실은 부분 실패로 처리합니다. 기존 클라이언트 필드는 보존하지만 엄격한 JSON 소비자는 추가 필드와 종료 코드 변화를 반영하십시오. ([#141](https://github.com/abruption/aptly/issues/141), [PR #146](https://github.com/abruption/aptly/pull/146))
- 통계 활성화: `aptly stats enable`이 첫 이벤트 전에 빈 DB를 초기화하고 기존 DB는 검증·보존합니다. 초기화 실패는 등록 설정이 남아 있어도 `partial`과 `statistics_store_initialization_failed`로 보고합니다. 조회는 DB를 생성·복구하지 않습니다.
- 출시된 기능 안내: 네 언어 가이드의 전송 범위 재검토와 Codex 계정 홈 정책 참조 절차를 현행화하고 기능별 최소 버전과 과거 우회 안내를 구분합니다. ([#142](https://github.com/abruption/aptly/issues/142), [PR #147](https://github.com/abruption/aptly/pull/147))
- 원장 사전 확인: Hook과 복구 티켓의 사전 확인을 읽기 전용으로 수행합니다. 조회만으로 원장 권한을 수정하거나 초기화하지 않으며 실제 쓰기 잠금·완료 결과·불명 결과 보호는 유지합니다. ([#143](https://github.com/abruption/aptly/issues/143), [PR #148](https://github.com/abruption/aptly/pull/148))
- 로컬 진단: `aptly doctor [--client codex|claude|all]`가 별도 JSON으로 로컬 등록·정책·패키지 버전과 원장을 관측합니다. 4MiB 초과 원장은 본문을 읽지 않으며 첫 원장 부재는 이력 미확인으로 표시합니다. 관측 중 파일 변경은 집계를 폐기합니다. 런처 실행·자격 저장소 조회·API 호출·상태 변경은 수행하지 않습니다. ([#144](https://github.com/abruption/aptly/issues/144), [PR #149](https://github.com/abruption/aptly/pull/149))
- MCP 진단: `get_routing_capabilities.runtime_diagnostics`가 응답 프로세스 버전·정책 소스 종류·시작 시점 자격 상태 표시·복구 슬롯 사용량을 제공합니다. 만료된 티켓도 슬롯을 차지하며 조회는 티켓을 갱신·삭제하거나 재시도 가능성을 검사하지 않습니다. 엄격한 MCP 소비자는 추가 객체를 허용해야 합니다. 기존 `aptly report` 스키마는 유지합니다.

## 업데이트와 호환성

게시 후 `npm install -g aptly@latest --allow-scripts=aptly` 또는 검증된 전역 설치의 `aptly update`로 갱신하십시오. 의도한 호스트 홈에서 `aptly setup --client all`을 실행하고 MCP·호스트를 재시작하십시오. Codex의 새 Hook은 `/hooks`에서 검토하고 승인하십시오. 키·전송 범위·원장·통계 이력을 초기화할 필요가 없습니다. [설치 안내](../guide/ko/installation.md)를 확인하십시오.

이전 버전에서 통계를 활성화했으나 이벤트가 없어 DB가 아직 없다면 의도한 홈에서 `aptly stats enable --client codex` 또는 `aptly stats enable --client claude`를 다시 실행하십시오. 기존 DB가 손상된 경우에는 자동 교체하지 않으므로 반환 사유를 검토하십시오.

`complete`는 조회 완료이고 추천·실행 성공이 아닙니다. CLI 버전, 디스크 등록 패키지 버전과 연결된 MCP의 버전은 별개입니다. 로컬 `doctor`는 연결된 MCP·Hook 신뢰·실행·재시작 필요 여부를 `unknown`으로 유지하며, 같은 버전만으로 설정 재로딩이나 전체 쓰기 프로세스의 중지를 증명하지 않습니다.

## 검증과 게시 상태

0.1.13 후보에서 회귀 테스트 793개와 빌드·문서·릴리스 검사, 격리 설치 tarball 및 fixture MCP·캐시 검증을 통과했습니다. 이 준비 검증은 유료 API 호출·native 자식 실행·실제 호스트 설정 변경 없이 수행했습니다. PR과 병합 main의 원격 CI는 각각의 정확한 HEAD에서 구분하여 확인합니다. 준비는 [#150](https://github.com/abruption/aptly/issues/150)에서 추적하며, 태그 생성·Actions OIDC 게시·registry 무결성·서명·provenance 검증은 별도 게시 단계입니다. 실제 게시가 완료되기 전에는 게시 성공으로 해석하지 마십시오.
