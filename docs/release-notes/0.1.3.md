2026-11-06에 `aptly@0.1.3`을 GitHub Actions OIDC로 게시하고 registry 파일·npm 서명·provenance를 검증했습니다. 확인 당시 npm `latest`는 0.1.3입니다.

## 주요 변경

- **보존된 기존 등록의 명시적 이전:** `--migrate-launcher --include-existing`으로 표준 Node·서버 실행 경로만 현재 빌드로 갱신할 수 있습니다. 기존 Aptly 소유 기록과 관리 환경변수·Hook·정책 일치를 요구하며 `mcp_created: false`는 유지합니다. 사용자 래퍼·소유 기록이 없는 등록·지원하지 않는 형식은 거절하고, 기본 이전 명령과 자동 설치는 기존 실행 경로를 계속 보존합니다.
- **명시적 패키지 업데이트:** `aptly update`는 실행 중인 패키지와 일치하는 전역 npm 설치를 검증하고 동일 prefix에 `aptly@latest`를 설치합니다. 로컬 설치·소스 체크아웃·심볼릭 링크로 연결한 설치·확인할 수 없는 경로는 거절합니다. `--ignore-scripts`로 호스트 설정을 유지하며, 완료 후 별도 `setup`과 호스트 재시작을 안내합니다.
- **dry-run의 잘못된 성공 보고 방지:** npm의 유효 설정이 `dry-run=true`이면 설치 전 `update_dry_run_enabled`로 중단합니다. 설정을 읽지 못하거나 결과가 불명확하면 `update_configuration_unverified`로 중단하며 실제 설치 없이 업데이트 성공을 보고하지 않습니다.
- **새 안정 버전 알림:** 일반 CLI의 성공한 대화형 실행에서 새 버전을 stderr로 안내합니다. stdin·stdout·stderr가 모두 터미널일 때만 확인하고 MCP 서버·자동 setup·추천/분류 경로·파이프·CI는 제외합니다. JSON stdout과 MCP·Hook 응답은 변경하지 않으며 업데이트를 자동 설치하지 않습니다.
- **설치 안내 개선:** 기본 명령에 `--allow-scripts=aptly`를 추가해 해당 설치에서 Aptly의 설치 스크립트를 명시적으로 허용합니다. npm 11.19.1의 미검토 스크립트 경고만으로 실행 차단을 단정하지 않으며, 옵션 미지원 시 사용할 수동 설정 대안을 안내합니다.

버전 알림은 공개 npm 버전 메타데이터만 조회하고 키·작업 요약·호스트 설정을 전송하지 않습니다. 네트워크와 본문 읽기를 최대 800ms·16KiB로 제한하며, 24시간 캐시와 실패 후 1시간 대기를 적용합니다. 조회·캐시 실패는 원래 명령을 실패시키지 않습니다. CLI 실행 환경에서 `APTLY_NO_UPDATE_NOTIFIER=1`로 확인을 끌 수 있습니다.

## 설치와 업그레이드

**먼저 기존 원장에 접근하는 다른 호스트·MCP·CLI 프로세스를 중지하십시오.** JSON 원장·`unknown`·비용·완료 캐시와 유효한 SQLite 잠금 파일을 삭제하거나 초기화하지 마십시오. 0.1.2 이전 버전에서 전환한다면 [설치·원장 이전 안내](https://github.com/abruption/aptly/blob/v0.1.3/docs/guide/ko.md#설치)의 오프라인 절차를 따르십시오.

0.1.2에는 `aptly update`와 버전 알림이 없으므로 최초 전환은 npm으로 수행해야 합니다. 다음 명령은 최신 안정 버전을 설치합니다.

```sh
npm install -g aptly@latest --allow-scripts=aptly
aptly setup --client all --mode defaults
aptly --version
```

옵션 미지원 npm이거나 설치 스크립트 실행 대신 직접 설정하려면 다음 대안을 사용하십시오. 사용자 전체의 npm 허용 설정은 변경하지 않습니다.

```sh
npm install -g aptly@latest --ignore-scripts
aptly setup --client all --mode defaults
```

0.1.3 이상을 설치한 뒤에는 검증 가능한 전역 설치에서 다음 명령을 사용할 수 있습니다.

```sh
aptly update
aptly setup --client all --mode defaults
```

업데이트는 기존 MCP 실행 경로·사용자 래퍼를 자동 전환하거나 API 키를 다시 저장하지 않습니다. 표준 등록의 실행 경로가 오래됐다면 해당 호스트만 지정하고, 보존된 기존 등록은 다음과 같이 먼저 변경 가능 여부를 확인하십시오.

```sh
aptly setup --client claude --migrate-launcher --include-existing --dry-run
```

결과와 로컬 등록을 검토한 뒤 `--dry-run` 없이 명시적으로 적용할 수 있습니다. 소유 기록을 삭제·편집해 검사를 우회하지 마십시오. MCP·호스트를 재시작하고 Codex에서는 `/hooks`의 신뢰 검토가 계속 필요합니다. 실제 운영 원장 이전이나 사용자 PC의 전역 업데이트는 이번 게시·검증 작업에서 수행하지 않았습니다.

## 배포와 검증

0.1.3 후보의 회귀 테스트 406개와 타입 검사·빌드·공개 패키지·다국어 문서 검사가 통과했습니다. 설치한 compiled CLI·exports·fixture MCP·캐시 smoke도 통과했습니다. 병합 후 main CI 7개도 통과했습니다. 공개된 0.1.2를 임시 전역 prefix에 설치해 새 npm 허용 옵션과 두 가짜 호스트의 자동 등록을 별도로 확인했으며, 이 시험을 0.1.3 게시 근거로 대신 사용하지 않았습니다.

[Actions 실행 42162474877 / attempt 1](https://github.com/abruption/aptly/actions/runs/42162474877/attempts/1)의 설치 시험·새 runner 패키징·OIDC 게시가 모두 성공했습니다. 소스는 `0ad227f0a007e434efde915d45b4002f04f6a3a9`, 태그는 `v0.1.3`입니다. 새 artifact와 registry 파일의 SHA-256·SHA-512 integrity가 일치했고, 정확한 0.1.3 SLSA v1 bundle과 인증서의 소스·태그·workflow·실행 identity를 검증했습니다. registry 전파를 읽기 전용으로 기다렸으며 게시를 재실행하지 않았습니다. 과거 버전의 검증 결과는 재사용하지 않았습니다.
