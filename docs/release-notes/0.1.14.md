# Aptly 0.1.14

Node 버전 변경에 견디는 선택형 POSIX 실행기를 추가합니다.

## 변경 사항

- `aptly setup --launcher stable`로 Node 버전 디렉터리 밖에 실행기와 런타임 의존성을 보존할 수 있습니다. 기존 Node와 npm 패키지 폴더가 삭제돼도 다른 지원 Node 설치본을 탐색합니다. Node 바이너리는 복사하지 않으며 Node.js 24 이상이 필요합니다. ([#154](https://github.com/abruption/aptly/issues/154), [PR #155](https://github.com/abruption/aptly/pull/155))
- 비공개 불변 세대, 파일 무결성 검사와 제한된 모듈 해석을 적용합니다. 설정·키·원장·통계는 런타임 사본에 포함하지 않습니다.
- 명시적 마이그레이션은 소유권이 확인된 MCP와 통계 관찰자를 함께 갱신합니다. 수정된 사용자 실행기는 자동 인수하지 않습니다. 진단은 오래된 런타임과 복구 명령을 표시합니다.
- 통계 관찰자의 비동기 셸 실행에서도 표준 입력을 보존하며, 설치 패키지 시험에서 원본 Node·패키지 삭제 후 MCP와 관찰자 실행을 검증합니다.

## 업데이트와 호환성

```sh
npm install -g aptly@latest --allow-scripts=aptly
```

기존 직접 실행 방식은 기본값으로 유지됩니다. macOS·Linux에서 안정 실행기로 전환하려면 의도한 호스트 홈에서 다음 명령의 dry run을 검토한 뒤 실행하십시오.

```sh
aptly setup --client all --launcher stable --migrate-launcher --dry-run
aptly setup --client all --launcher stable --migrate-launcher
```

MCP·호스트를 재시작하고 Codex의 변경된 Hook은 `/hooks`에서 검토·승인하십시오. 키·전송 범위·원장·통계를 초기화할 필요가 없습니다. Windows의 기존 직접 실행 방식은 지원하지만 stable 옵션은 지원하지 않습니다. 안정 실행기는 Node 관련 주입 환경변수를 제거하므로 사용자 Node 실행 옵션과의 호환성을 검토하십시오. 이후 패키지 업데이트에서도 보존된 런타임의 명시적 마이그레이션이 필요합니다. 상세 제약과 복구 절차는 [설정 가이드](../guide/ko/configuration.md)를 참고하십시오.

## 검증과 게시 상태

PR #155의 정확한 HEAD에서 원격 CI 19개 검사가 성공했습니다. Node 24·26의 macOS·Ubuntu 설치 시험은 원본 Node·패키지 제거 및 빈 PATH 조건에서 fixture MCP와 등록된 통계 관찰자의 실제 실행을 확인했습니다. 유료 API·native 자식 실행이나 기존 호스트 세션의 재로딩을 증명하는 검증은 아닙니다. 이번 버전 준비와 게시 결과는 별도로 기록합니다.
