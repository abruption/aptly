# Aptly 0.1.2 게시 및 provenance 검증

2026-11-06에 `aptly@0.1.2`를 GitHub Actions의 npm OIDC 경로로 게시하고 registry의 파일과 provenance를 검증했습니다. 이 기록은 [Issue #41](https://github.com/abruption/aptly/issues/41)의 실제 게시 근거입니다. 일반적인 절차는 [배포 안내](../RELEASING.md)를 참고하십시오.

| 확인 항목 | 결과 |
|---|---|
| npm 게시 | 확인 완료 — `aptly@0.1.2`, 확인 당시 `latest=0.1.2` |
| registry 파일과 준비 artifact 일치 | 확인 완료 — SHA-256 및 SHA-512 integrity 일치 |
| npm 서명·provenance 검증 | 확인 완료 — 정확한 버전의 SLSA v1 bundle 확인 |
| 인증서 identity·소스·실행 연결 | 확인 완료 — GitHub CLI 검증 및 기대값 대조 |

설치 시험은 전용 일회성 runner에서 실행했습니다. 별도의 준비 runner가 같은 태그를 checkout하고 잠긴 의존성을 lifecycle script 없이 설치하여 빌드·검증·pack했습니다. 게시 job은 그 준비 job의 source SHA와 artifact ID만 받아 검증한 archive를 게시했습니다. 세 job 모두 성공했습니다.

게시 전 GitHub `npm` environment의 배포 규칙이 사용자 승인한 태그 `v*`만 허용하는 상태임을 조회·확인했습니다. 별도 required reviewer가 있다는 뜻은 아닙니다. 로컬 npm 관리자 설정 조회는 유효한 로컬 로그인 인증이 없어 `E401`을 반환해 Trusted Publisher 목록을 새로 확인하지 못했습니다. 이전 게시에서 확인한 `abruption/aptly`·`publish.yml`·environment `npm` 연결 정보를 기준으로 진행했으며, 이번 실행의 실제 Actions OIDC 게시와 아래 인증서 identity 검증을 각각 확인했습니다. 로컬 관리자 목록을 재확인했다고 주장하지 않습니다. 워크플로에는 token secret 대체 인증이 구성되지 않았습니다.

## 파일 무결성

준비 artifact의 `release-manifest.json`·실제 archive와 registry에서 별도로 내려받은 archive를 비교했습니다. source SHA·태그·버전이 위 identity와 일치하며 SHA-256도 동일했습니다.

```text
SHA-256
1e3a22ba145f0ac0d737edad568e207615cb28f92c7713a94fc39b9552c92e5a

Registry dist.integrity (SHA-512 SRI)
sha512-EBNGa0eSBS/45tWSHOuoP9EawQm64WlO3B8elOz73ErHNLbTB5JzHLs6YYhgtsGj3e9JJHT69gGQ1Oxj/JFwtg==
```

registry archive에서 계산한 SHA-512 SRI도 `dist.integrity`와 일치했습니다. 실제 게시 archive는 이전 로컬 후보가 아니라 이 Actions 실행에서 생성한 artifact를 기준으로 확인했습니다.

## 서명과 provenance

`npm 11.19.1`에서 lifecycle script를 끈 격리 설치 후 `npm audit signatures --json --include-attestations`를 실행했습니다. 검증은 성공했고, `verified` 배열에서 `aptly@0.1.2`의 `https://slsa.dev/provenance/v1` bundle을 확인했습니다. 종료 코드나 빈 오류 배열만으로 provenance 존재를 판단하지 않았습니다.

이 bundle과 registry archive를 `GitHub CLI 2.103.3`의 `gh attestation verify`로 검증했습니다. SHA-512, 저장소, source SHA, 태그 ref, 정확한 인증서 workflow identity를 지정하고 self-hosted runner를 거부하는 조건에서 성공했습니다. 검증된 인증서의 다음 필드를 기대값과 대조했습니다.

| 인증서 필드 | 일치한 값 |
|---|---|
| `issuer` | `https://token.actions.githubusercontent.com` |
| `sourceRepositoryURI` | `https://github.com/abruption/aptly` |
| `sourceRepositoryDigest`·`buildSignerDigest` | `885214315f7505097bad17da2c1ee49ec3840446` |
| `sourceRepositoryRef` | `refs/tags/v0.1.2` |
| `subjectAlternativeName`·`buildSignerURI` | `https://github.com/abruption/aptly/.github/workflows/publish.yml@refs/tags/v0.1.2` |
| `runInvocationURI` | `https://github.com/abruption/aptly/actions/runs/42151554506/attempts/1` |
| `runnerEnvironment` | `github-hosted` |

따라서 게시 성공과 provenance 검증 성공을 각각 확인했습니다. 이 결과는 해당 archive의 출처·무결성과 위 실행 identity의 연결을 확인한 것이며, 모델 품질·비용 절감이나 모든 호스트 환경의 동작을 인증하지 않습니다.

## 확인 범위

이 버전의 파일·artifact·attestation을 새로 받아 검증했으며, 0.1.1의 검증 성공을 대체 근거로 사용하지 않았습니다. 게시 job을 재실행하거나 버전을 중복 게시하지 않았습니다.

검증에는 유료 모델 API 호출·전역 설치·기존 Claude Code 또는 Codex 설정 이전을 포함하지 않았습니다. 공개 기록에는 인증정보·신뢰 설정 ID·개인 경로를 포함하지 않습니다.

기존 영속 원장의 업그레이드에는 모든 관련 writer 중지와 동시 전환이 필요합니다. [원장 잠금·오프라인 전환 안내](../LEDGER_LOCKING.md)를 확인하십시오. 이 게시·검증 작업에서 실제 운영 원장을 이전하지 않았습니다.
