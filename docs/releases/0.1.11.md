## 조사와 검증

Orca 소스와 설치본 1.4.256에서 기본 홈의 같은 이름 MCP 등록을 관리형 홈에 동기화하고 계정 로컬 MCP 환경 변경을 정본에 승격하지 않는 경로를 확인했습니다. 당시 파일을 쓴 정확한 프로세스는 추적하지 않았습니다. 호스트 내부 패치는 포함하지 않습니다.

수정 후보의 전체 테스트 665개와 문서·빌드·공개 범위 검사, fixture MCP/cache·설치 tarball 검사를 통과했습니다. 별도 에이전트 검토가 발견한 전달 설정 복원 누락은 회귀 테스트로 보완하고 재확인했습니다. 맥미니 로컬과 맥북 SSH의 격리 설치에서 서로 다른 전송 범위의 두 합성 계정에 정본 MCP 테이블 동기화를 세 번 반복해 정책 바이트 보존·통계 조회·누락 홈 거부를 확인했습니다. 임시물은 정리했으며 이 시험의 유료 API 호출과 native 자식 실행은 0입니다.

SSH 시험은 처음에 원격 PATH에서 Node를 찾지 못해 결과가 없었습니다. 이를 성공으로 처리하지 않고 등록된 Node 경로를 사용해 재실행한 뒤 결과를 확인했습니다. 실제 사용자 설정·키·원장·통계 이력·신뢰를 변경하지 않았습니다. 이 결과를 실행 중 MCP의 갱신·실제 모델 수용·비용 절감 증거로 해석하지 않습니다.

버전 갱신 후 후보 검증 결과는 준비 PR 본문에 기록했습니다. 최종 병합 main과 실제 게시 검증은 위와 아래에 별도로 기록합니다.

## 실제 호스트 전환과 한계

두 Mac의 등록 서버를 0.1.11로 갱신하고 기본/정본 및 선택 계정에서 명시적 `codex-home` 참조 전환·읽기 전용 설정 점검·통계 조회를 완료했습니다. 각 홈의 정책 바이트·전송 선택·Hook·통계 설정과 소유권·원장 참조와 바이트를 보존했습니다. 새 MCP 프로세스의 0.1.11 버전과 기존 전송 범위도 확인했습니다.

기존 호스트 세션의 재연결·재로딩은 관측하지 않았습니다. 유료 호출·native 자식 실행은 0이며 이 확인은 실제 모델·effort 적용, 사용자 수용·품질·비용 절감이나 전체 호스트 설정의 출처를 인증하지 않습니다. 통계의 기본 비활성·POSIX 지원·별도 native 메타데이터 동의와 Hook 신뢰 검토는 유지합니다.

## 알려진 문제와 임시 실행 방법

0.1.11에서 `codex-home` 정책 참조를 선택한 뒤 `CODEX_HOME`이 없는 일반 터미널에서 CLI 설정 명령이 실패하는 문제를 [#135](https://github.com/abruption/aptly/issues/135)로 추적합니다. 읽기 전용 점검으로 재현했으며 이 릴리스에 수정이 포함됐다고 주장하지 않습니다. 기본 홈을 대상으로 실행할 때는 다음처럼 환경을 명시하십시오. 관리형 계정에서는 해당 계정의 의도한 절대 홈 경로를 사용하십시오.

```sh
CODEX_HOME="$HOME/.codex" aptly setup --check --client codex
```

일반 CLI의 홈 선택 문제와 실행 중 MCP 서버의 엄격한 `CODEX_HOME` 검사는 구분합니다. MCP의 누락·잘못된 홈 거부를 우회하거나 다른 계정 홈으로 대체하지 마십시오.
