준비 PR #86이 병합된 정확한 main CI 성공을 확인한 뒤 해당 소스에 태그를 생성했습니다. 설치 시험과 패키징은 별도 runner에서 수행했고, 새 패키징 runner의 artifact를 게시 job이 재검증해 게시했습니다. 준비 기반 main `0f0da280f0d9b5dca17c0b61fb18b6e180f1c3a5`와 이번 실제 게시 소스는 구분합니다.

GitHub `npm` environment가 `v*` 태그만 허용하고 별도 required reviewer가 없음을 읽기 전용으로 확인했습니다. 로컬 npm 관리자의 Trusted Publisher 목록은 새로 조회하지 않았습니다. 실제 OIDC 게시 및 아래 인증서로 결과를 확인했으며 token secret 대체 인증은 사용하지 않았습니다.

## 무결성·서명

이번 실행의 manifest·archive와 registry에서 별도로 내려받은 파일이 일치했습니다. manifest의 소스·태그·버전·dist-tag도 위 identity와 같았습니다.

```text
SHA-256
e1e049f4bb074248a9519c706aa35414423c40b50d0e5e387a5f06fb39bcc6ab

SHA-512 SRI
sha512-1rN91qd6+zAaWQG6aNDBePG7UmMQ/O3ef25vLbAhpGcwznXOrpLMG1sHjWwpKZESPrh+CcdJjOAc62yNzma3Pg==
```

SHA-512 SRI는 registry `dist.integrity`와 일치했습니다. 이전 버전의 archive·digest·검증 결과를 재사용하지 않았습니다.

`npm 11.19.1`에서 정확한 버전을 lifecycle script 없이 격리 설치하고 `npm audit signatures --json --include-attestations`를 수행했습니다. 최종 invalid·missing은 없고, 정확한 `aptly@0.1.6`의 SLSA v1 bundle 한 개를 확인했습니다.

`gh version 2.103.3 (2026-10-26)`의 `gh attestation verify`로 bundle과 registry archive를 검증했습니다. SHA-512·repository·source SHA·태그·정확한 workflow 인증서 identity를 제한하고 self-hosted runner를 거절했습니다. 다음 값이 기대값과 일치했습니다.

## 전파 대기·검증 재시도

게시 뒤 provenance endpoint가 초기 404를 반환해 읽기 전용 조회로 200 응답을 기다렸습니다. 그 뒤 첫 격리 npm 설치는 `ETIMEDOUT`(종료 코드 196)으로 실패했습니다. 실패 단계·npm 코드·종료 코드를 보존했으며, 이 오류의 정확한 요청 URL이나 원인을 단정하지 않습니다. provenance 전파 관측과 설치 시간 초과를 같은 원인으로 취급하지 않습니다.

같은 소스·태그·게시 실행·attempt를 기준으로 artifact를 새로 받아 읽기 전용 검증을 재수행했고 최종 무결성·npm 서명·GitHub 인증서 검증이 모두 통과했습니다. 태그를 이동하거나 게시 job을 재실행하거나 같은 버전을 중복 게시하지 않았습니다.

격리 검증 임시 파일은 정리했습니다. 전역 설치·운영 원장·호스트 설정·키는 변경하지 않았고 새 유료 모델/native 시험은 수행하지 않았습니다. 준비 회귀 478개와 기존의 제한된 native·독립 CLI 검수는 [릴리즈 노트](../release-notes/0.1.6.md)에 원래 범위로 기록합니다. 이번 출처 검증은 모든 호스트·모델의 지원, 사용자 의도·실행의 인증 또는 새 비용 절감 측정이 아닙니다.
