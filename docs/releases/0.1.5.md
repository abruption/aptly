# Aptly 0.1.5 게시 및 provenance 검증

2026-11-07에 `aptly@0.1.5`를 GitHub Actions OIDC로 게시하고 registry 파일과 provenance를 검증했습니다. [Issue #75](https://github.com/abruption/aptly/issues/75)의 실제 게시 근거입니다. 사용자 변경은 [한국어 릴리즈 노트](../release-notes/0.1.5.md), 절차는 [배포 안내](../RELEASING.md)를 참고하십시오.

PR #74가 승인된 PR #72의 스택 브랜치 변경까지 main에 통합한 소스를 사용했습니다. 준비 회귀 453개와 PR CI 통과 후, 정확한 main 소스의 CI 성공을 별도로 확인했습니다. 격리 설치 시험과 릴리즈 패키징은 별도 runner였으며, 새 패키징 runner의 artifact를 게시 job이 재검증해 게시했습니다.

게시 전에 GitHub `npm` environment가 `v*` 태그만 허용함을 읽기 전용으로 확인했습니다. 로컬 npm 관리자의 Trusted Publisher 목록은 새로 조회하지 않았습니다. 실제 OIDC 게시와 인증서 identity로 이번 배포를 검증했으며 token secret 대체 인증은 사용하지 않았습니다.

## 무결성과 서명

이번 실행의 artifact와 registry에서 별도로 내려받은 archive가 일치했습니다.

```text
SHA-256
8114aadb50eb43e3f84dd19ead23b23651c5eecc9d41c9081e6826a52536fae1

SHA-512 SRI
sha512-AHOJeVjFSWgf46x0hm4aX5zt3vrjNdligefYJcZl8mp8DyBKHZ4jP7wg17OkqXO2mIQ5yQmBLLCar49TVof8SA==
```

SHA-512 SRI는 registry의 `dist.integrity`와 일치했습니다. artifact manifest의 source·태그·버전·dist-tag도 위 identity와 같았습니다. 이전 버전의 archive나 검증 결과를 재사용하지 않았습니다.

`npm 11.19.1`에서 정확한 버전을 lifecycle script 없이 격리 설치하고 `npm audit signatures --json --include-attestations`를 수행했습니다. 최종 결과에 invalid·missing이 없고, 정확한 `aptly@0.1.5`의 SLSA v1 bundle 한 개가 있음을 확인했습니다.

`gh version 2.103.3 (2026-10-26)`의 `gh attestation verify`로 그 bundle과 registry archive를 검증했습니다. SHA-512·repository·source SHA·태그·인증서 workflow identity를 제한하고 self-hosted runner를 거절했습니다. 다음 인증서 값이 기대값과 일치했습니다.

| 인증서 필드 | 일치한 값 |
|---|---|

| sourceRepositoryURI | `https://github.com/abruption/aptly` |
| sourceRepositoryDigest·buildSignerDigest | `eb283ab1394a777c572c89a75c5436f4c95af302` |
| sourceRepositoryRef | `refs/tags/v0.1.5` |

## 확인 지연과 범위

게시 job 성공 직후 `latest`가 잠시 0.1.4로 조회됐습니다. 두 차례 독립 npm 서명 검증은 `E404`로 실패했고, 실패 단계·종료 코드·npm 코드를 보존했습니다. 별도 provenance URL 조회도 404였다가 200으로 바뀌었습니다. 최초 audit 오류의 정확한 URL은 기록되지 않았으므로, 별도 조회 결과만으로 개별 실패 원인을 단정하지 않습니다.

같은 소스·태그·run·attempt의 artifact를 다시 받아 읽기 전용 검증을 수행했고 최종 무결성·npm 서명·GitHub 인증서 검증이 모두 통과했습니다. 게시 job이나 태그를 재실행하지 않았습니다.

격리 검증의 임시 파일은 정리했습니다. 전역 설치, 운영 원장·호스트 설정·키는 변경하지 않았고 새 유료 모델·native 시험도 수행하지 않았습니다. 기능 개발 단계의 제한된 native 결과는 [복구 계약](../SPAWN_CONTEXT.md)에 별도로 기록하며, 이번 출처 검증을 모델 품질·비용 절감·모든 호스트 지원의 인증으로 해석하지 마십시오.
