## 전파와 검증 범위

게시 workflow 성공 뒤 초기 조회에서 npm latest 0.1.9와 attestation 404를 관측해 보존했습니다. 이후 정확한 0.1.10과 latest를 확인하고 같은 게시 실행의 6번째 attestation 조회에서 200을 확인했습니다. 태그·게시 job은 반복하지 않았으며, 이번 게시 후 검증에서 실패한 npm 설치·서명 재시도는 없었습니다. 검증용 임시 artifact·설치 폴더는 정리했습니다.

준비 후보의 테스트 612개(실패·생략 0), 타입 검사·빌드·fixture MCP, 공개 범위 검사(소스 290개·패키지 94개), 격리 tarball의 CLI·compiled exports·MCP·캐시와 4개 언어 문서 검사가 통과했습니다. 이번 게시 실행은 별도 disposable 설치 시험 runner와 새 검증/pack runner를 분리하고 publish job에서 같은 artifact ID와 소스 SHA를 재검증했습니다.

전역 설치·실제 호스트 설정·자격·운영 원장·예산·배포 보호 규칙을 변경하지 않았습니다. 통계는 기본 비활성이고 POSIX의 명시적 설정과 Codex native 메타데이터 추가 동의·신뢰 검토를 요구합니다. 모델 증거는 실제 effort·사용자 수용·품질·전체 실행 이력·토큰/비용 합계가 아닙니다. 이번 게시 검증은 새 제품 품질·유료 분류/native 실행 평가를 수행하지 않았으며 CLI·fixture·CI와 실제 호스트 적용의 증거를 구분합니다.
