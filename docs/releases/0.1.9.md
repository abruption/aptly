## 서명과 provenance

일회성 비공개 HOME·npm 설정·캐시에서 정확한 npm 버전을 lifecycle 없이 설치하고 `npm audit signatures --json --include-attestations`를 실행했습니다. invalid·missing은 0건이며 정확한 0.1.9의 SLSA v1 bundle을 확인했습니다. 실제 archive에 SHA-512·저장소·소스 digest·태그 ref·인증서 identity·GitHub-hosted 제한을 지정한 `gh attestation verify`도 통과했습니다. 격리 설치의 compiled CLI는 0.1.9를 출력했습니다.

## 전파와 검증 범위

attestation 초기 404를 보존하고 7번째 조회에서 200을 확인한 뒤 서명 검증을 수행했습니다. 같은 소스·태그·run/attempt를 대상으로 읽기 전용으로 확인했으며 태그·게시 job을 반복하지 않았습니다. 이번 게시 후 검증에서는 실패한 npm 설치나 서명 재시도가 없었습니다. 검증용 임시 artifact·설치 폴더를 정리했습니다.

준비 후보의 무료 테스트 556개(실패·생략 0), 타입 검사·빌드·fixture MCP·4개 언어 문서 검사·공개 범위 검사(소스 270개·패키지 86개), 격리 tarball의 CLI·compiled exports·MCP·캐시 검증이 통과했습니다. compiled CLI 출력은 0.1.9입니다. 게시 workflow는 별도 disposable runner의 설치 시험과 새 runner의 검증·pack을 분리했습니다.

전역 설치·실제 호스트 설정·키·원장·예산·배포 보호 규칙을 변경하지 않았으며 새 제품 유료/native 평가도 수행하지 않았습니다. Linux 메타데이터 진단은 실제 자격 저장소의 활성화·잠금 해제·키 저장 성공을 보증하지 않습니다. `setup --check`는 쓰기 없는 시점별 설정 계획이며 실행 중 호스트를 인증하지 않습니다. CLI 버전 출력, fixture·CI 결과, 게시 출처와 제품 품질·실제 native 적용의 증거를 구분합니다.
