# 요구사항과 범위

2026-11-05 현재 사용자 결정은 호스트 내부 패치 보류와 추천 전용 preview 우선이에요. 직접 추천의 입력 계약은 Router.advise로 분리했고 [ROADMAP](ROADMAP.md)에 구현·검증 근거를 기록했어요. 전체 host evidence와 native 자동 적용은 추천 출시의 전제가 아니에요.

분류는 OpenAI Decisions, 실행은 기존 Codex/Claude 인증으로 분리해요. 초기 공개 범위는 로컬 stdio MCP·최소 CLI·보수적 우선순위 진단이며 운영 자동 라우팅 제품으로 검증된 상태는 아니에요.

| ID | 요구사항과 현재 검증 |
|---|---|
| R01 | 코어·MCP·CLI·Hook에서 같은 추천 정책 사용 |
| R02 | 분류 키는 MCP 환경에서만 사용, 인자·결과·로그 비노출 |
| R03 | 사용자별 로컬 stdio, 필수 원격 서비스 없음 |
| R04 | 검증된 레지스트리에서 기본 6개와 명시 선택한 후보만 사용, 임의 모델·effort·명령 거부 |
| R05 | 명시 model/effort·역할·환경·관리 설정 보존. 불명 출처는 unknown |
| R06 | 역할·fork·문맥·권한 보존, resume 재분류 거부 |
| R07 | 작업 label만으로 맥락을 추정하지 않고 needs_context/유지 |
| R08 | timeout·거절·잘못된 응답·키 오류·예산 소진 시 유지 |
| R09 | MCP는 spawn을 생성하거나 모델 실행 인증을 소유하지 않음 |
| R10 | native MCP Hook 연결과 별도 자식 MCP 초기화 비용 구분 |
| R11 | Codex effort와 Claude 설정 구분, 확인한 조합만 지원 |
| R12 | 완료 캐시·요청 충돌·unknown 재시도 방지·지연 응답 격리 |
| R13 | 원장별 일/누적/동시성/크기/지연/추정 비용 가드, 계정 청구 상한과 구분 |
| R14 | 최소 요약·구조화 특성만 분류, 원문·자격 자동 수집 없음 |
| R15 | 작업·응답은 데이터이며 정책·명령·권한으로 실행하지 않음 |
| R16 | 추천·Hook 요청·실제 자식 모델/effort·완료·품질을 별도 근거로 기록 |

전체 effective settings를 Hook만으로 알아내는 기능, 배포용 자동 설치·제거, 일반 작업의 품질·총비용 평가, 다중 분류 제공자와 원격 호스팅은 현재 범위 밖이에요. [설정 경계](CONFIGURATION.md)와 [검증](VALIDATION.md)을 함께 읽어요.
