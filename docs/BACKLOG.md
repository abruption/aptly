# 개선 과제

각 항목의 상태를 기준으로 읽어요. AD 항목은 현재 추천 preview에서 완료한 작업이고, IMP-001은 후보 배열만 후속 지시에 따라 반영했고 나머지는 제안·미구현으로 남겨요. 미구현 항목을 실제 지원 설정으로 해석하지 않아요.

## 현재 추천 preview 잔여 작업 — 2026-11-05

사용자 지시로 호스트 내부 패치를 보류했어요. 현재 실행 순서는 아래와 같으며 상세 근거·완료 기준은 [ROADMAP](ROADMAP.md)을 기준으로 해요. 이후 사용자가 ROADMAP 구현과 필요한 유료 호출을 허용했고 아래 항목을 수행했어요. 상세 완료 근거는 ROADMAP과 ADVISORY_RESULTS에 있어요.

| ID | 상태 | 잔여 작업 |
|---|---|---|
| AD-001 | 완료·무료 회귀 | 직접 추천과 Hook 적용의 provenance 조건 분리, 보존/캐시/원장 회귀 |
| AD-002 | 완료·예제/안내 | 실제 동작하는 추천 요청·결과 예제와 fixture/Decisions 수동 사용 안내 |

호스트 resolver 패치·broker·원자적 native dispatch는 보류한 별도 확장이며 AD 항목의 선행 조건이 아니에요. 기존 구현·과거 증거는 보존해요.

## IMP-001 — 사용자 라우팅 정책과 환경변수 확장

- 등록일: 2026-11-03
- 상태: 부분 반영 — 후속 사용자 지시에 따라 0.1.0 초안에 제공사별 추천 후보 배열(화이트리스트)을 구현했어요. 사용자 지정 강제 덮어쓰기·제외 목록·제외 경로와 나머지 정책 확장은 미착수예요.
- 우선순위·일정: 미정
- 목적: 사용자가 추천·자동 적용의 범위를 조절할 수 있도록 설정 표면을 확장해요.

### 요청한 항목

| 항목 | 제안 타입 | 결정할 내용 |
|---|---|---|
| 사용자 지정 덮어쓰기 | boolean | 기본값은 false를 제안해요. true일 때 기본값·호출별 인자·역할·환경 설정 중 어떤 출처까지 변경할 수 있는지 명확히 정의해야 해요 |
| 추천 포함 모델 | string[] | 모델 ID와 프로필 ID 중 입력 단위, 미지정·빈 배열의 차이, 허용 카탈로그와의 관계를 정해야 해요 |
| 추천 제외 모델 | string[] | 포함 목록과 겹칠 때 우선순위, 모델·effort 조합 처리, 필터 후 후보가 없을 때 동작을 정해야 해요 |
| 동작 제외 경로 | string[] | 세션 cwd와 작업 대상 경로 중 적용 기준, 상대 경로 기준점·glob·정규화·symlink·플랫폼 차이를 정해야 해요 |

배열형 환경변수는 실제로 문자열로 전달되므로 JSON 배열 등의 인코딩·검증 방식을 정해야 해요. 환경변수 이름과 구체적 기본값은 아직 확정하지 않았어요.

### 함께 검토할 설정

- 기존 shadow/apply 모드의 환경변수 노출 여부와 private 설정 파일과의 우선순위
- 호출 수·추정 예산·timeout·동시성·입력 크기 제한의 사용자 설정
- 설정 변경·후보 제외·덮어쓰기 보류 이유의 안전한 진단과 report 반영

이는 추가 검토 후보이며 이번 과제에서 모두 구현하기로 확정한 목록은 아니에요. 기존에 구현된 내부 정책과 새 환경변수 지원을 구분해요.

### 설계 결정과 수용 기준

1. 사용자 덮어쓰기는 명시적인 opt-in 범위와 보존 대상의 출처를 구분해요. 조직 제한·권한·샌드박스·문맥·fork를 우회하는 기능으로 확대하지 않아요. 현재의 보존 정책은 후속 설계·구현 전까지 유지해요.
2. 모델 목록은 신뢰된 카탈로그와 호스트 허용 범위 안에서 후보를 제한해요. 임의 모델·명령·권한을 추가하는 경로로 사용하지 않아요. 포함·제외 충돌과 후보 소진 시 기존 인자를 유지하는 동작을 명세해요.
3. 제외 경로에 해당하면 원격 분류 호출 전에 판별해 추천·재작성을 건너뛰고 원래 호출을 유지하는 방향으로 설계해요. 경로를 확인할 수 없는 경우도 명시적인 보수 정책을 정해요.
4. 환경변수·private 정책 파일·호스트 설정·호출별 입력의 우선순위와 잘못된 값의 처리 방식을 문서화해요. 작업 본문이나 MCP 요청이 신뢰된 운영자 설정을 바꾸지 못하게 해요.
5. 적용 정책 변경을 요청 digest·캐시·원장과 연결해 이전 정책의 결과를 잘못 재사용하지 않아요. 불명 유료 호출을 새 ID로 자동 재시도하지 않아요.
6. 기본값, opt-in, 포함·제외 충돌, 빈 목록·후보 소진, 잘못된 배열·불명 출처, 경로 제외와 API 미호출, 플랫폼별 경로 해석의 회귀를 준비해요.
7. report에는 적용 여부와 고정된 이유 코드만 반영하고, 실제 키·환경변수 값·개인 경로 목록을 첨부 파일에 넣지 않아요.

구현 전에 덮어쓰기의 정확한 의미와 설정 우선순위를 먼저 결정해요. 이 과제를 등록한 사실은 현재 CLI·MCP에 해당 환경변수가 추가됐다는 뜻이 아니에요.
